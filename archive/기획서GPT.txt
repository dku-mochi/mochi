모찌 iOS 앱 기획서 v1.0

1. 서비스 개요

1.1 서비스명

모찌

서비스명 “모찌”는 다음 두 문장에서 가져온다.

“뭐든지 찍어보세요.”
“이거 뭐였지?”

즉, 모찌는 사용자가 캡처하거나 저장해둔 정보를 나중에 다시 찾고 활용할 수 있도록 돕는 AI 기록 관리 에이전트이다.

⸻

1.2 한 줄 소개

모찌는 스크린샷, 링크, 텍스트 메모를 AI가 자동으로 분석해 일정, 할 일, 지식, 기록으로 분류하고 다시 찾아주는 iOS 기반 멀티모달 기록 관리 앱이다.

⸻

1.3 핵심 가치

모찌의 핵심은 단순 저장이 아니다.

사용자는 이미 많은 것을 저장한다.

* 스크린샷
* 카카오톡 링크
* 유튜브 영상
* 인스타그램 게시물
* 사파리 페이지
* 학교 과제 공지
* 회의 메모
* 아이디어

문제는 저장 이후다.

저장은 쉽지만, 다시 찾고 활용하는 것은 어렵다.

모찌는 이 문제를 다음 원칙으로 해결한다.

입력은 더 쉽게, 분류와 회수는 AI가.

⸻

2. 문제 정의

2.1 사용자 문제

사용자는 일상에서 정보를 빠르게 저장하지만, 저장 위치가 여러 앱에 분산되어 있다.

예를 들어 다음과 같은 상황이 반복된다.

* 유튜브 영상을 나중에 보려고 저장했지만 잊어버림
* 카카오톡으로 받은 링크를 다시 찾기 어려움
* 스크린샷은 많지만 어떤 이유로 찍었는지 기억나지 않음
* 학교 과제를 캡처해두었지만 마감일을 놓침
* 메모, 사진, 캘린더, 브라우저 북마크가 각각 따로 움직임
* 저장한 정보가 일정인지, 할 일인지, 학습 자료인지 사용자가 직접 분류해야 함

⸻

2.2 기존 방식의 한계

기존 도구	장점	한계
카카오톡 나에게 보내기	빠르게 저장 가능	시간순으로 쌓여 찾기 어려움
인스타그램 저장	콘텐츠 저장 쉬움	인스타 내부 콘텐츠에 한정
유튜브 나중에 볼 동영상	영상 저장 쉬움	영상 내용 기반 검색 어려움
사파리 책갈피	웹페이지 저장 가능	사용자가 직접 폴더 관리 필요
iOS 사진앱	스크린샷 자동 보관	왜 찍었는지 맥락 파악 어려움
메모앱	자유롭게 작성 가능	분류와 회수는 수동

모찌는 이 문제를 단일 입력 경로 + AI 자동 분류 + 자연어 회수로 해결한다.

3. 제품 목표

3.1 제품 목표

모찌의 제품 목표는 다음 세 가지다.

첫째, 사용자가 어떤 앱에서든 기록을 쉽게 저장할 수 있게 한다.

둘째, AI가 기록의 의도를 파악해 자동으로 분류한다.

셋째, 사용자가 나중에 자연어로 기록을 다시 찾고 활용할 수 있게 한다.

4. iOS 플랫폼 전략

4.1 iOS 공유 시트 기반 입력

모찌의 핵심 입력 방식은 iOS Share Extension이다.

iOS에서는 사용자가 다른 앱에서 공유 버튼을 눌러 Share Extension을 실행할 수 있다. Apple 문서에서도 iOS 사용자는 시스템 제공 UI에서 Share Extension을 선택해 현재 보고 있는 콘텐츠를 다른 앱으로 보낼 수 있다고 설명한다.  ￼

모찌는 이 구조를 활용해 다음 콘텐츠를 받는다.

* 이미지
* 스크린샷
* 텍스트
* URL
* 선택된 텍스트
* 일부 앱에서 공유 가능한 미디어 메타데이터

Share Extension은 별도 프로세스로 실행되며, 앱 본체와 리소스나 권한을 자동으로 공유하지 않는다는 점을 고려해야 한다. 따라서 App Group, shared container, 서버 업로드 큐 설계가 필요하다.  ￼

⸻

4.2 백탭 기반 입력

iPhone의 Back Tap 기능은 사용자가 기기 뒷면을 두 번 또는 세 번 탭해 단축어를 실행할 수 있다. Apple 지원 문서에서도 Back Tap을 통해 Shortcuts를 실행할 수 있다고 설명한다.  ￼

모찌는 이를 직접 시스템 레벨에서 제어하는 것이 아니라, 사용자가 Shortcuts를 등록하도록 안내하는 방식으로 접근한다.

중요한 UX 포인트:

“모찌가 백탭을 직접 등록한다”가 아니라
“사용자가 버튼을 눌러 단축어 등록 흐름으로 이동한다”가 정확하다.

따라서 온보딩에서는 다음처럼 설명한다.

앞으로 아이폰 뒷면을 빠르게 두 번 탭하면 모찌를 불러올 수 있어요.
아래 버튼을 누르면 단축어 등록을 도와드릴게요.

⸻

4.3 OAuth 로그인

회원가입/로그인은 다음 두 가지를 지원한다.

* Apple 로그인
* Google 로그인

Google Sign-In for iOS는 Xcode 프로젝트 설정과 의존성 추가가 필요하며, Google 공식 문서는 iOS/macOS 앱에서 Google Sign-In 구성 절차를 제공한다.  ￼

Apple 로그인은 iOS 앱에서 프라이버시 친화적인 로그인 방식으로 사용될 수 있다. 실제 배포 시에는 Apple Developer Program, Identifier, Entitlement, 서버 검증 흐름을 함께 설계해야 한다.  ￼

6. 정보 분류 체계: 4-Intent

모찌는 모든 기록을 네 가지 Intent로 분류한다.

Intent	설명	예시	생명주기
일정	특정 시간에 발생하는 이벤트	내일 3시 팀 회의	시간 도래 후 완료/기록화
할 일	완료 여부가 중요한 작업	보고서 제출하기	완료 전까지 활성
지식	다시 학습하거나 참고할 정보	RAG 구조 설명 글	장기 보관
기록	맥락 보존이 중요한 메모	회의 내용, 감상, 일상	장기 보관 또는 요약

⸻

6.1 Intent별 처리 방식

일정

* 날짜/시간 추출
* 장소 추출
* 참석자 추출
* 캘린더 등록 후보 생성
* 알림 후보 생성

할 일

* 작업명 추출
* 마감일 추출
* 우선순위 추정
* 체크리스트 생성
* 홈 제안 영역에 표시

지식

* 핵심 주제 추출
* 요약 생성
* 태그 생성
* 임베딩 저장
* 자연어 검색 대상 포함

기록

* 원본 맥락 보존
* 간단 요약 생성
* 날짜별 타임라인 저장
* 필요 시 추후 지식화 가능

⸻

6.2 Intent 생명주기

모찌의 차별점은 “저장 시점”뿐 아니라 “저장 이후”까지 본다는 점이다.

예를 들어 “내일 3시 팀 회의”는 일정이다. 이 정보는 회의 전에는 알림이 중요하고, 회의 후에는 회의 기록으로 전환될 수 있다.

“보고서 제출하기”는 할 일이다. 완료 전에는 홈에서 계속 제안되어야 하지만, 완료 후에는 과거 기록으로 이동한다.

“RAG 구조 설명 글”은 지식이다. 시간이 지나도 검색 가치가 있으므로 장기 보관된다.

따라서 모찌는 모든 정보를 동일하게 저장하지 않고, Intent별 생명주기에 따라 다르게 관리한다.

7. IA: 앱 정보 구조

탭바는 총 4개 항목으로 구성한다.

텍스트 없이 아이콘만 사용하되, 접근성을 위해 VoiceOver label은 반드시 제공한다.

탭	아이콘 제안	역할
홈	house	요약, 추천, 최근 모찌
질문	message bubble / sparkle chat	AI 질의응답
모찌들	calendar	날짜 기반 기록 탐색
검색	magnifying glass	전체 검색

중앙 플로팅 버튼은 제거한다.

이유:

* 기능이 불명확함
* 백탭과 Share Sheet가 이미 핵심 입력 경로임
* 홈 화면에서 시각적 노이즈가 생김
* 사용자가 “+ 버튼을 눌러야만 저장 가능하다”고 오해할 수 있음

대신 입력은 다음 세 가지로 통일한다.

1. 백탭
2. Share Sheet
3. 홈 우측 상단의 작은 입력 버튼 또는 설정 안의 수동 입력

8. 페이지별 상세 기획

8.1 스플래시 페이지

목적

8.5 질문 페이지

목적

챗봇 UI.

하지만 일반 챗봇과 다르게 AI가 어떤 도구를 사용했는지 일부 보여주는 구조를 적용한다.

⸻

기본 구성

* 상단 제목: 질문
* 채팅 메시지 영역
* 입력창
* 추천 질문 칩
* Tool 사용 상태 표시

⸻

추천 질문 예시

* 지난주 저장한 자료 정리해줘
* 이번 달 할 일 알려줘
* AI Agent 관련 모찌 찾아줘
* 발표 준비에 필요한 기록만 모아줘
* 마감일 있는 것들 보여줘

⸻

Tool 사용 표시 방식

AI가 작업 중일 때 다음과 같이 표시한다.

모찌가 기록을 찾고 있어요
의미 검색 중…
관련 모찌 5개 발견
일정 후보 확인 중…
답변 정리 중…

너무 개발자스럽게 vector_search, web_fetch 같은 이름을 그대로 보여주기보다는 사용자 친화적 문구로 변환한다.

내부 Tool과 사용자 표시

내부 Tool	사용자 표시
vector_search	관련 기록 찾는 중
db_query	저장된 모찌 확인 중
web_fetch	링크 내용 확인 중
calendar_tool	일정 후보 확인 중
todo_tool	할 일 확인 중
summarizer	요약 정리 중

⸻

답변 구조

AI 답변에는 반드시 근거가 되는 모찌를 표시한다.

예시:

지난주 AI Agent 관련 모찌는 총 3개예요.
가장 중요한 내용은 “LLM이 상황에 맞게 도구를 선택해 사용하는 구조”였어요.

참고한 모찌

* LangChain Agent 구조 설명 영상
* 발표 대본 메모
* Tool use 정리 글

10.3 모델 전략

기본 전략은 다음과 같다.

* 이미지 분석: 멀티모달 LLM
* OCR: 별도 OCR 또는 멀티모달 모델 내장 기능 비교
* 텍스트 분류: LLM
* 임베딩: 별도 embedding model
* 검색: RDB + Vector DB Hybrid Search

사용자가 언급한 “Gemini 3.5 Flash”는 구현 시점의 실제 사용 가능 모델명과 API 스펙을 확인한 뒤 확정하는 것이 좋다. 기획서에는 특정 모델명을 강하게 박기보다 다음처럼 쓰는 편이 안전하다.

AI 모델은 Gemini 계열의 멀티모달 모델을 우선 검토하며, 비용·속도·정확도 실험 결과에 따라 교체 가능한 구조로 설계한다.

백탭 모달	필수	메모/스크린샷 입력

캘린더 연동	P2	일정 등록

⸻

22. 가장 중요한 UX 원칙

모찌의 UX는 이 원칙을 지켜야 한다.

사용자가 정리하게 만들지 않는다.
사용자는 보내기만 하고, 모찌가 정리한다.

그래서 앱의 핵심 버튼은 “추가하기”가 아니라 다음에 가까워야 한다.

* 맡기기
* 저장하고 정리하기
* 모찌에게 보내기
* 캡처하고 정리하기

이게 모찌의 브랜드와 가장 잘 맞습니다.
