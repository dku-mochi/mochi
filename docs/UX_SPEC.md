## 1. 핵심 사용자 시나리오

### 1.1 시나리오 A — 첫 가입

1. 앱 실행 → 스플래시 → Apple/Google 로그인
2. 온보딩 4단계 (§3.3): 모찌 소개 → 백탭 설정(검증까지) → 공유 저장 → 캡처 자동 정리
3. 홈 진입

### 1.2 시나리오 B — 백탭으로 메모 저장

1. 아이폰 뒷면 두 번 탭 → Shortcuts → snippet 카드에서 "메모" 선택
2. 모찌 풀스크린 메모 모달 → text area 입력 → 저장
3. AI 가 Intent 분류 → 홈의 최근 모찌에 표시

**입력 예시**: "다음 주까지 발표 대본 수정하기"
**AI 결과**: Intent=할 일, 제목="발표 대본 수정", 마감 후보="다음 주"

### 1.3 시나리오 C — 백탭으로 스크린샷 저장 (snippet 흐름)

1. 학교 LMS 과제 화면에서 백탭
2. 단축어가 현재 화면을 자동 캡처 + PNG 를 모찌 stash → 외부 앱(LMS) 위에 모찌 snippet 카드가 떠오름. **LMS 화면은 사라지지 않음** — 사용자 컨텍스트 보존.
3. snippet 카드의 "캡쳐" 버튼 탭 → 카드만 사라지고 LMS 가 계속 보임. 백그라운드에서 로컬 저장(상세 메커니즘·fallback 은 §3.7).
4. 다음에 모찌 앱을 열면(또는 푸시로) 새 캡처가 분석 완료 상태로 떠오름.

**AI 결과 예시**: Intent=일정, 제목="과제 제출", 마감 후보="다음 주 금요일 23:59"

### 1.4 시나리오 D — 유튜브 링크 공유

1. 유튜브에서 공유 버튼 → 모찌 선택
2. Share Extension → URL 수신 → 서버에서 WebFetch / 메타데이터 조회
3. 요약 → Intent 분류 → 지식 또는 기록으로 저장

| 영상 유형 | 분류 |
|---|---|
| LangChain Agent 강의 | 지식 |
| 게임 하이라이트 | 기록 |
| 과제 제출 방법 안내 | 할 일 |
| 행사 일정 안내 | 일정 |

### 1.5 시나리오 E — 자연어 회수

**질문 예시**: "지난주에 저장한 AI Agent 관련 자료 정리해줘."

1. 채팅 탭 랜딩의 입력바 모양 버튼(또는 능력 칩)에 자연어 입력 — 홈에는 입력바가 없다(검색은 검색 탭, 질문은 채팅 탭으로 역할 분리, §3.4 2026-06-19)
2. **대화 풀스크린(push)의 첫 메시지**로 전환 (2026-06-10 라우팅 전환 — 칩이 광고하는 추천·수정·요약은 검색 탭이 수행 불가. back 으로 랜딩에 그대로 복귀)
3. 모찌가 기록을 뒤져 답변 — 본문 위첨자 출처 뱃지(¹²) + 근거 미니카드(탭 → 상세) + 접힌 "과정 보기". 수정/삭제/일정/알림/메모 요청은 proposal 확인 카드로 — 사용자 확정 탭 전까지 아무 일도 일어나지 않는다. 확정 결과는 로컬 미러에 바로 merge 돼 캘린더·홈에 즉시 보이고, 일정 확정은 **실제 iOS 캘린더(EKEvent, 시간 없으면 종일, `end_date` 있으면 기간 이벤트)·미리알림(todo→EKReminder)에도 등록**된다(권한 거부 시 카드가 설정 링크 안내, 재확정 안전 — ingest 멱등. 권한 확보 후 EK save 실패는 best-effort — 기록 생성이 본질).
   > ⚠️ **known-drift (스코프 컷 2026-06-10)**: ① 채팅 `updateItem` 으로 날짜를 수정해도 이미 등록된 EKEvent 는 따라가지 않는다(EK 식별자 미영속). ② 메모 확정(`create_memo`)이 분석 후 schedule/todo 로 분류돼도 시스템 캘린더엔 등록되지 않는다(무확정 자동 등록은 동의 문제 — **사용자가 명시 확정한 직행 생성만 등록**: 채팅 일정 확정 + 캘린더 탭 "일정 추가"(2026-06-15)). 등록 로직은 `CoreIntegrations.SystemCalendarRegistrar` 공용(채팅 전용 아님 — 2026-06-15 추출). 필요해지면 EK 식별자 영속 + 분석 완료 시 동의 UI 로 확장.

> 채팅 탭 = **랜딩**(2026-06-10 push 전환 — 입력 독이 탭바 위에 상주하면 이중 바로 읽히고, TabView 안 입력바는 키보드 inset 이 어긋나는 고질 버그가 있다): 모찌 인사 + 능력 칩 4종(홈과 동일 문구) + 입력바 *모양* 버튼(진짜 TextField 아님). 어떤 진입이든 **대화 풀스크린을 push** — 탭바가 사라지고 입력 독이 키보드에 정확히 붙는다(메신저 표준: 카카오톡·X DM). 대화 중 스크롤은 **일반 메신저식 bottom anchored** — 전송 후 질문을 화면 상단에 고정하지 않고, 사용자가 바닥 근처에 있을 때만 새 메시지·스트리밍 답변·키보드 변화가 최신 내용으로 따라간다. 입력 중 전송해도 키보드는 유지한다. 입력바 버튼 탭 = 활성 세션 복원 + 컴포저 자동 포커스, 칩 = 첫 메시지 즉시 전송, 지난 대화(랜딩·대화 양쪽 시계 아이콘) → 시트(스와이프 삭제, 탭 재개). assistant 버블의 미니 모찌 아바타는 제거(26pt 로 뭉개짐). 세션은 비활성 30분이 지나면 조용히 새 대화로 분리(사용자가 세션을 관리하지 않는다 — 미션). 서버 live 배선 완료(POST-as-SSE + 워치독 75초) — 백그라운드로 스트림이 끊겨도 run 은 서버에서 완주하고, 복귀 시 스냅샷 재조회(+running 2초 폴링)로 "돌아왔더니 답이 와 있다".

## 3. 페이지별 기획

### 3.1 스플래시

- 파스텔 연보라 그라데이션 배경 + **모찌가 걷는 애니메이션**(`MochiWalk00~24` 25프레임 시퀀스 24fps, 화면 정중앙, 은은한 발치 접지 그림자). Veo 3.1 image-to-video 로 생성한 walk 을 크로마키·seamless loop 처리한 투명 프레임 에셋(원본·소스는 루트 `mochi-walk-assets/`). 이전 정적 `SplashMochi`·가로등 조명 연출을 대체.
- 카피·장식 텍스트 없음 — 아이콘만. 등장 시 **모찌 뒤(가려진 중앙)에서 생일폭죽(파티 포퍼)이 터져** 색종이가 솟구쳐 흩날리는 축하 연출(`Canvas`+`TimelineView` 파티클, 선형 drag 낙하·회전·3D flip·좌우 흔들림, `Reduce Motion` 시 생략). 색은 주간 리포트 카드와 같은 `HomeDesign.Color` 팔레트(blush/peach/mint/sky/purple).

### 3.2 로그인

- 모찌 캐릭터 + Apple 로그인 / Google 로그인 버튼 + 약관·개인정보 동의

### 3.3 온보딩 튜토리얼

4단계 (`OnboardingPage`): ① 모찌 소개 → ② 백탭 설정 → ③ 공유 저장 소개 → ④ 캡처 자동 정리 소개 → 홈.

전환: NavigationStack push(좌우 슬라이드) — 스와이프 pager 는 백탭 게이트를 건너뛰게 하고(거부 시 인디케이터 desync) 전환도 끊겨, push 네비게이션으로 바꿨다(전진은 CTA 버튼으로만, 건너뛸 surface 없음). 하단 점 인디케이터 제거, 네비게이션 바는 **배경만 투명**(그라데이션 위에 시스템 뒤로 버튼 노출, 디자인 유지)으로 뒤로가기 제공. 모찌 캐릭터 중심, 텍스트는 한 번에 1~2 문장.

**백탭 설정(단계 ②)은 단순 안내가 아니라 끝까지 끌고 가는 체크리스트다** — 백탭(1순위 입력)은 단축어 *추가* 와 뒷면 탭 *연결* 이라는 분리된 두 행동이 모두 끝나야 살아나므로:
1. **단축어 추가** — iCloud Shortcuts 링크로 모찌 단축어(`Take Screenshot → 모찌 화면 캡쳐`) 가져오기
2. **뒷면 탭 연결** — 설정 가이드 시트가 `손쉬운 사용 > 터치 > 뒷면 탭 > 두 번 탭 > 모찌` 경로를 **실제 설정 화면 스크린샷 세로 캐러셀**(탭할 항목만 스포트라이트로 강조)로 안내
3. **실동작 검증** — 사용자가 실제 뒷면을 두 번 탭하면 App Group 핸드셰이크로 백탭이 모찌 intent 에 도달했음을 확인하고 "백탭이 작동해요"를 모찌가 먼저 알린다(폴링 90초 타임아웃). 검증 중에는 `CaptureScreenshotIntent` 가 진짜 캡처 대신 hit 만 기록해 쓰레기 저장을 막는다 (§3.7).

검증 성공 또는 "나중에 할게요"(skip) 전에는 다음 페이지로 넘어가지 않는다(미설정 채 홈 도착 방지). 온보딩은 첫 실행 때 한 번만 자동 노출하고, 이후에는 홈의 완전 빈 상태와 설정의 "온보딩 다시 보기"에서 재진입할 수 있다. 재진입 온보딩이 끝나면 기존 홈/설정 위치로 돌아간다.

### 3.4 홈

위에서 아래 순서 (`MochiHomeView` — **회수 전면화**, 2026-06-19 회의 반영). 홈의 무게중심은 검색·질문 입력이 아니라 **모찌가 먼저 꺼내 주는 회수**다 — "찾으러 들어왔다가 잊은 기억을 발견해 '아, 맞다!'"(PRODUCT §1.5).

0. **상단 floating bar** — 회수 히어로 위에 떠 있는 한 줄: 좌측 **날짜**(예 "6월 19일 목요일" — 컨텍스트), 우측 **검색(돋보기)·알림(bell)·즐겨찾기(별)·설정(gearshape)** frosted glass(블러) 작은 원형 버튼(34pt, 알림 버튼 2026-06-19 추가 — 검색 다음·즐겨찾기 앞). 알림 → 알림 페이지 push(§3.4c). 큰 제목을 여기 두면 앱 이름처럼 읽히므로(2026-06-19 피드백) 회수 섹션 제목은 콘텐츠 헤더로 내리고, navbar 자리엔 날짜만 둔다(캘린더·할일 앱 컨벤션). 별도 내비바·장식용 모찌 아이콘 없음 — 그 영역까지 회수에 내줬다. 검색 아이콘 → 검색 탭 전환(query 없이 — 탐색은 검색 탭의 역할, 탭별 역할 분리). bar 자체 배경 띠는 두지 않는다 — 날짜·검색·즐겨찾기·설정이 **각자 frosted 칩(ultraThinMaterial)**이라 배경 없이도 콘텐츠 위에서 글자·아이콘이 잘 보인다(글자 뒤만 블러, 모던, 2026-06-19). 배경 띠를 깔면 답답해 보여 칩 방식으로 갔다.
1. **회수 히어로 (심장·전면)** — 콘텐츠 첫 줄이 섹션 헤더(제목 **"모찌가 골라봤어요"**[회수 주체가 모찌임을 드러내는 멘트, 2026-06-19] + 우측 "모두 보기" → 자세히 §3.11), 그 아래 상단을 가득 채우는 큰 무한 **3D 코버플로우**(화면 높이 ~48%, `RecallHeroView` — 좌우 이웃 카드가 Y축으로 기울어 원근 속으로 물러난다, **수평 축**만 써 대각선 흐름은 없음; 어두운 무대가 아니라 **밝은 공간**이 무대라 먼 카드는 배경색으로 옅게 녹고(공기원근) 그림자 2겹으로 떠 있으며, **덱 뒤가 초점 카드 reason 색으로 물들어 넘길 때마다 색으로 숨쉰다** — 2026-06-19 최상급 패스), 덱 아래 가운데 페이지 인디케이터. 실 캡처 이미지가 주인공, 좌우 드래그·관성 스냅·선택 햅틱, 가운데 카드 탭 → 카드가 그대로 확대되며 원본 상세로 **hero zoom**(최근 카드·검색 카드와 같은 전환 — `HeroSourceFrames`+`ZoomDetailPresentation`, server PK 역매핑 경로에 hero 보존, 2026-06-19). 열어본 카드는 **즉시 빠지지 않고** 상세를 닫고 돌아와 카드 자리에 착지한 뒤 spring 으로 우아하게 사라진다(`recallDetailClosed` — 닫기버튼은 비행 ~0.48s 후, 드래그는 비행 완료 직후. "열면 피드에서 빠진다"는 규칙·`opened` 반응 보고는 유지, 제거 타이밍만 dismiss 이후로). 비면(cold-start) 마스코트 중앙 정렬 일러스트 카드("모찌가 곧 골라드릴게요"). **검색바·대화 진입 프레임은 홈에서 제거**(탐색은 검색 탭, 질문은 채팅 탭으로 역할 분리 — 홈탭 큐레이션·회수 성능에 집중).
2. **확인이 필요해요** — needsReview("헷갈려요") 배너. 푸시를 놓쳐도 여기가 진실원천 (있을 때만 표시, 탭 → 시트).
3. **이번 달 모찌 리포트** — 카테고리 카드 그리드를 대체(§3.4b 진입점 이동). "기억 N개를 저장했어요" 한 줄 헤드라인 + 이번 달 카테고리 비중을 한 줄 **stacked 막대 + 범례**(상위 3개 + "그외")로 요약. 카드 상단 **오른쪽에서 작은 `mochi-peek` 캐릭터가 살짝 엿봄**(폭 ~30%, 검증 offset 비율, 기존 마스코트 아이콘 대체) — 카드는 더 얇게. 범례는 **탭 가능한 칩 2열**(연한 tint 배경 + chevron — 범례처럼 안 보이고 버튼임이 드러나게, 2026-06-19), 탭 → 그 서랍을 3D 턴테이블로 push(§3.4b). 우상단 "자세히"(캡슐 — 회수의 "모두 보기"와 형태·거리로 구분, 2026-06-19 피드백) → 돌아보기. **월간** 표본 — 전체를 보여주면 최신성이 거의 안 반영돼 이번 달로 묶는다. 옛 홈 "이번주 리포트" 감성을 잇되 주간 → 월간 + 카테고리 중심. 카테고리 라벨은 정규화 결과(DOMAIN_DESIGN §4).
   - **돌아보기 상세(`MonthlyDigestView`/`MonthlyDigestFeature`, 2026-06-19 재설계 · 2026-06-20 월간화)** — 리포트 카드 우상단 "자세히"가 여는 화면. 제목 "이번 달 돌아보기". ① 히어로(**월 네비게이터** ◀ 2026년 6월 ▶ — 과거 달을 넘겨봄, 이번 달이면 ▶ 비활성; + 쌓인 기억 수 + **카테고리 요약 바**(세그먼트+레전드, 2개 이상일 때만, 상위 5 + "외 N개") + 모찌 한마디 말풍선) → ② "이런 걸 모았어요" **카테고리별 가로 레일** — 그 달 항목 전부 가로 스크롤(썸네일 탭→상세, 우측 페이드로 "더 있다"), 헤더 우측 "전체 보기" 퍼플 칩(탭 영역 한정) → 검색 탭을 그 카테고리로 필터("그 외"는 칩 숨김), 카테고리 5개 초과 시 "그 외 N개 더 보기"로 접음 → ③ 푸터. **"아직 안 끝났어요"(미해결 todo·일정) 섹션 제거** — todo·일정 회수는 캘린더 소관, 리포트는 순수 회고("찾기"는 검색 위임). 홈 카드·상세 모두 **월간**(`MonthlyDigestFeature.monthInterval`) 단위로 정합 — 레일·개수는 100% 로컬(달 오프셋만큼 과거 조회), 서버 digest(LLM greeting + 카테고리 정규화 write)는 **현재 달만** 호출(과거 달은 정적 회고 인사 + 로컬 집계, 재정규화·비용 회피).
4. **최근에 보낸 것들** — 최근 저장 항목 가로 스크롤(12개 limit, 카드 탭 → 상세 zoom 전환). 카드는 chrome 최소화 — 타입(스크린샷/메모/URL)·4-Intent 라벨은 **노출하지 않는다**(타입은 카드 형태로, intent 는 배관이라 행동으로만 드러남 — PRODUCT §5). 서브텍스트는 출처·시간(회수 단서)만. **캡처 이미지 렌더 정책**(카드·상세 헤더·hero 비행 공통): 세로 캡처=fill 크롭(메인 콘텐츠가 중앙일 확률 높음), 가로 캡처=fit(좌우 끝 정보도 중요, 정지 화면은 블러 레터박스 / 비행 중은 단색) — 카드↔상세가 같은 모양이라 hero 전환에서 안 튄다.

우하단 + FAB = 빠른 입력(메모·링크·사진·카메라). "모찌가 정리하고 있어요"(analyzing) 접힘 섹션은 새 홈에서 제외 — 분석 대기는 사용자 행동이 불필요해 시각 비중을 두지 않는다.

> 옛 `HomeFeature`/`HomeView`("자동성의 예외 처리 인박스")는 코드상 아직 공존하나 비활성 — `MainTab` 은 `MochiHomeFeature` 를 쓴다. 정리(삭제)는 회수 기반 추가 개선 일단락 후.

### 3.4a 즐겨찾기 (2026-06-14)

홈 헤더 별 → push 되는 회수 화면(`FavoritesView`, WeeklyDigest 와 같은 path 패턴). 사용자가 검색 카드·상세에서 즐겨찾기한 항목만 모아 2열 그리드(`RecentMochiCard` 재사용)로 보여준다 — 항목 탭 → 공용 상세(delegate present). 비어 있으면 별 아이콘 + "기록 상세나 검색에서 별을 눌러 두면 여기서 모아 볼 수 있어요" 안내.

**미션 정합**: 즐겨찾기는 사파리 책갈피식 "사용자가 직접 폴더 관리"(PRODUCT §2.2 비판)가 아니라, **사용자가 모찌에게 주는 "중요" 신호**다 — 능동 회수의 주체는 여전히 모찌(PRODUCT §1.5). 이 화면은 모찌가 그 신호로 다시 꺼내 보여주는 회수 표면이지, 사용자가 뒤지는 상설 폴더가 아니다(그래서 홈 메인 피드의 큐레이션을 침범하지 않는 부차 진입점). 서버 동기화라 기기 재설치 후에도 복원된다.

### 3.4b 카테고리 턴테이블 (2026-06-17)

홈 "이번 달 모찌 리포트" 의 범례 항목 → push 되는 화면(`CategoryCarouselView` / `CategoryCarouselFeature`, WeeklyDigest·즐겨찾기와 같은 path 패턴). 한 카테고리의 기억들을 **3D 누운 원판(LP 턴테이블)**으로 펼쳐, 좌우 드래그로 굴리면 관성으로 돌다 가장 가까운 커버에 스냅된다(시안 `docs/home-carousel-prototype.html` 의 scroll-velocity 3D planes 복제). 앞쪽 커버가 초점 — 하단 패널이 그 기억의 종류·시각·제목을 보여주고, 초점 커버 탭 또는 "이 기억 열기" → 공용 상세(delegate present, hero 없는 중앙 scale — 회전 커버라 hero frame 불안정).

- **집계**: **이번 달 표본**(`listCaptured` 당월, 상한 800)을 `analysis.category`(없으면 fallback)로 묶어 개수 내림차순. 리포트 막대·범례는 상위 3 + "그외", 턴테이블 진입은 범례가 든 `CategoryBucket`(월간 items). 턴테이블 커버는 카테고리당 상위 30개로 상한(표시 개수 ≠ 커버 수 — 프로토타입과 동일 의도). 색은 `MochiCategoryPalette`(6색) 인덱스 순환 — 리포트 막대와 턴테이블이 같은 색.
- **모션**: 커버 위치는 연속값 `rotation`(카드 단위)에서 계산하고, 각 커버의 `CoverTransform3D`(`Animatable`)가 `rotation` 보간으로 매 프레임 재배치한다(별도 타이머 루프 없이 `interpolatingSpring` 으로 관성·스냅). reduce motion 이면 진입 회전 연출 생략.

**미션 정합**: 카테고리 그리드·턴테이블은 즐겨찾기(§3.4a)와 같은 결의 **부차 탐색 표면**이다 — 능동 회수의 주체는 여전히 모찌(채팅·회수 한 칸·알림, PRODUCT §1.5). "내가 무엇을 얼마나 모았나"를 한눈에 보고 그 서랍을 즐겁게 들춰보는 진입점이지, 사용자가 직접 분류·정리하게 강요하는 상설 폴더가 아니다(홈 메인 피드 큐레이션을 침범하지 않음). 라벨은 모찌가 부여한 정규화 category 를 그대로 보여줄 뿐 사용자가 만들지 않는다.

### 3.4c 알림 페이지 (2026-06-19)

홈 상단 bell 버튼 → push 되는 알림 화면(`NotificationsPageView` / `NotificationsPageFeature`, 즐겨찾기·턴테이블과 같은 path 패턴). **이전엔 홈 본문에 있던 "예정된 알림" 섹션을 이 페이지로 옮기고**(홈은 회수·리포트·최근에 집중 — 알림은 별도 표면으로 분리), 새 "받은 알림" 탭을 더해 상단 segmented Picker("예정된 알림"/"받은 알림")로 전환한다.

- **예정된 알림 탭** — 모찌가 보낼 예정인 미래 마감·일정 + **예약 회수(spaced)** 알림(`GET /recall/upcoming`, fire_at 오름차순). spaced 는 RecallHero(식어가는 지식 in-app 회수)와 별개로 "앞으로 보낼 예약 알림"이라 여기 노출한다(2026-06-21, "다시 보기" 보라 배지로 구분). recall(트랙C 즉시발송)은 pending 미래로 안 머물러 자연 제외. 홈에서 통째로 옮겨온 `UpcomingNotificationsView` 재사용 — 각 행 3액션(끄기 veto·미루기 프리셋·직접 고르기 DatePicker)·"모찌가 정하고 나는 조정한다" 그대로. **veto 의미는 kind 별**: deadline/nudge 는 그 plan 영구 cancel(시리즈 중단), spaced 는 "이번 회차만 건너뛰기"(plan 유지 → 다음 회차는 예정대로). 빈손이면 안내 일러스트.
- **받은 알림 탭** — 모찌가 이미 보낸 알림(`GET /recall/history` → `SentNotificationEntry`, sent_at 내림차순). **읽기 전용** — 종류 아이콘(deadline/nudge/recall) + title/body + 발송 시각 + 상태 칩(읽음=opened / 지나침=dismissed / 안 읽음). 안 읽은 알림은 왼쪽 보라 띠로 부드럽게 강조. 빈손이면 안내. 조정 액션 없음("이미 보낸 것"의 기록).

**미션 정합**: 알림 페이지는 모찌가 능동으로 보낸/보낼 알림의 타임라인이다 — 회수의 주체는 여전히 모찌(PRODUCT §1.5). 사용자는 예정 알림을 끄거나 옮길 뿐(통제), 지난 알림은 받은 기록을 되짚어 보는 안전망이다. 둘 다 실패 격리(한 탭 로드 실패가 다른 탭을 막지 않음).

### 3.4d 설정 (2026-06-22 재설계)

홈 상단 설정(gearshape) → push 되는 화면(`SettingsView`/`SettingsFeature`, 즐겨찾기·알림 페이지와 같은 path 패턴). 회색 시스템 `Form` → **앱 톤 카드 섹션**(HomeDesign 토큰·`cardShadow`, 다른 회수 표면과 같은 시각 언어)으로 재설계. 죽은 컨트롤(Server Endpoint·캘린더/미리알림 동기화 토글 — base URL 하드코딩·미배선)은 제거.

- **계정** — 아바타(이름 이니셜) + 이메일·이름. Keychain `AuthSession`(`authCoordinator.currentSession`)에서 읽음. 이름 비면 "모찌 사용자" 폴백. Apple 비공개 릴레이 이메일(`@privaterelay.appleid.com`)은 의미 없는 주소 대신 **"Apple로 로그인"** 표시.
- **알림** — 권한 상태 칩(허용됨/꺼짐/미설정, `UNUserNotificationCenter` 조회) + "iOS 설정에서 관리"(`openSettingsURLString` 딥링크). 앱 내 회수/분석 알림 on/off 토글은 서버 선호 API 미존재로 후속.
- **프라이버시** — "민감 캡처는 항상 이 기기에만" 토글(PRIVACY §5.3 이행). 켜면 고신뢰 민감 감지 시 선택 시트 없이 `localOnly`. `SensitiveCapturePreference`(AppGroup 공유)로 ShareExtension 이 읽는다.
- **정보** — 온보딩 다시 보기(기존) · **이용약관·개인정보처리방침**(2026-06-23, 공개 repo `dku-mochi/legal` GitHub Pages → 외부 Safari 아닌 인앱 `LegalWebView`(WKWebView) 공통 `.sheet(item:)` 표시) · 앱 버전(`Bundle`).
- **로그아웃** — destructive. 기존 경로(`delegate → RootFeature.requestSignOut`).

### 3.5 검색 (회수)

검색 탭은 **3 phase 화면** — `query` 만으로 자동 분기 (시안 #34-36, 2026-06-10 전면 재구현 / 2026-06-13 focused 화면 제거):

| phase | 트리거 | 화면 |
|---|---|---|
| `.idle` | query 빈 상태 (포커스 여부 무관) | 타입 드롭다운 + 카테고리 칩 + 2col 그리드(전체 모찌) |
| `.results` | 검색어 입력 + 결과 ≥ 1 | Intent 필터칩 + 결과 요약 + 2col 그리드 |
| `.empty` | 검색어 입력 + 결과 0 | 물음표 모찌 + "전체에서 다시 찾기" + "필터 초기화" |

**검색바 포커스는 별도 화면이 아니다** (2026-06-13 회의 — 카드 그리드가 검색바 탭에 갑자기 사라지는 단절이 어색 + 마스코트 인사·빠른 검색 거의 미사용 + 빠른 검색은 `.idle` 타입 필터칩과 기능 중복). 포커스 시 그리드는 그대로, 키보드 + **최근 검색 칩 한 줄**(검색바 아래, 최근 검색어 있을 때만, "모두 지우기" 포함)만 얹힌다.

**두 종류 필터** — 검색에선 Intent 가 *주된 분류 단서가 아닐 수* 있어(사용자가 자기 모찌의 의도를 정확히 모를 수 있음 — PRODUCT §5 노출 원칙과 정합) 화면별로 분리:
- 기본 화면(`.idle`) = **타입 드롭다운 + 카테고리 칩**(2026-06-17 재설계):
  - **타입 드롭다운**(좌측 고정, 기존 "전체" 칩 자리): 메뉴 = 전체 / 링크 / 스크린샷 / 메모. *어디서 받았나* 단서. **미확인 제거**(needsReview 는 홈 "지금 확인" 버킷이 담당). 트리거 라벨은 미선택 시 **"종류"**, 선택 시 그 타입명(아래 카테고리 "전체" 칩과 "전체" 중복을 피한다).
  - **카테고리 칩**(가로 스크롤, 기존 타입 칩 자리): 전체 + 정규화 category(쇼핑/방문/취미·자기계발/일상/… — 주간 리포트와 같은 소스, 전체 기록 기준 많은 순). *무엇에 관한 기억인가* 단서.
  - 둘은 **AND** 동시 적용. 신규 유저(카테고리 없음)면 칩 행은 "전체"만.
- 결과 화면(`.results`/`.empty`) = **Intent** 5칩: 전체 / 일정 / 할일 / 지식 / 기록. 검색 결과를 의도별로 좁힘.
- Intent 분류 자체는 폐기 X — 홈/캘린더/알림의 배관은 그대로.

**카드** — masonry 2-column (좌우 독립 LazyVStack + 예상 높이 균형 분배). **이미지/타이포 모자이크** (2026-06-12 재설계 — 배지·날짜·출처 chrome 전부 제거, 카드의 *형태*가 타입을 말한다. 타입·날짜는 필터칩·상세·VoiceOver 라벨이 담당). 그리드는 좌우 10pt(칩·요약 row 는 pageH 14 유지) + 셀 간 6pt 이음새 + radius 16, 테두리·그림자 없음:
- 스크린샷(+로컬 이미지): **2:3 풀블리드 이미지** center 크롭(캡처의 어느 부분이 중요한지 모르므로 위쪽을 가정 X) + 하단 **휘도 적응형 스크림**(가시 영역 하단 35% 평균 휘도에 비례, 흰 스크린샷일수록 진하게) + 흰 제목(최대 3줄) overlay, ~275pt. 인스타 탐색탭 패턴
- 링크: purple 파스텔 타이포 타일 — 제목 → **멘션 필**(실제 파비콘 + 도메인, 흰 캡슐 — 회수 단서), 138pt. 파비콘은 `https://<host>/favicon.ico` 직접 로드(제3자 프록시에 도메인 노출 X) + 실패 시 도메인 첫 글자 타일 폴백(`FaviconTile`, DesignSystem)
- 메모: butter / 스크린샷(이미지 없음): sky / 미확인: ink 파스텔 타일 — 제목 → 본문 preview(인용 워터마크), 138pt. 타일 색 = 타입 필터칩 activeBg 와 동일 매핑
- 제목은 `displayTitle` 위계 + "[출처앱: …]" 메타 strip. 분석 전 항목은 "모찌가 정리하고 있어요" (메타줄 삭제로 "분석 중" 칩도 제거). semantic("비슷한 기억") 구분도 시각 표시 제거, VoiceOver 만 유지

**키보드 dismiss** (2026-06-17 키보드 toolbar 제거) — 항상 떠 있던 ✓ 바 + 0건일 때 키보드 위 "물어보기" 캡슐을 둘 다 제거. 둘 다 redundant 였다(✓ 는 스크롤·return 과 중복, 키보드 위 캡슐은 빈 결과 화면의 같은 CTA 와 중복). 이제 dismiss = 스크롤·return·**콘텐츠 영역 탭**(`simultaneousGesture` 라 카드·칩·드롭다운 탭은 그대로 통과하며 키보드만 함께 내려감). 포커스 해제 시 최근 검색 칩 줄도 함께 내려감(별도 화면이 없어 phase 는 변하지 않는다). 빈 결과 escalation 은 `SearchEmptyResultView` 안의 "모찌에게 물어보기" CTA 하나로 일원화(키보드 내리면 바로 노출). 검색바 X 는 query 있을 때만(전체 reset). **검색 탭 reselect** — 탭바 검색 탭 재탭 시 filter+query reset → `.idle` 그리드 복귀.

> **배선 상태 (2026-06-11 실연결 완료)**: 그리드 = 로컬 Realm(`listRecent(200)` + `observeChanges` 자동 재로드, 홈 패턴), 저장 0 이면 빈 상태 화면. **2단 검색** — 키 입력 중 로컬 token 매칭(`LocalSearchService`, 즉답) + return 제출 시 `POST /search`(RAG) 의미 검색 보강(citations 서버 id → 로컬 역매핑, literal 우선 + semantic 추가). 최근 검색어 UserDefaults 실저장(최대 10). 빈 결과 "모찌에게 물어보기" → 채팅을 query 첫 메시지로 push. 삭제 = 홈 규약(서버 soft delete + 로컬 hard delete). 카드 탭 → 상세 hero present.

### 3.6 캘린더

날짜 기반 탐색 (`MochiCalendarFeature`):
1. **월간 캘린더** — 칸을 **점 3종(단일 시각 언어)** 으로 칠한다: 일정(sky, active schedule 의 `payload.date`) · 할 일 마감(butter, active todo 의 `payload.deadline ?? payload.date`) · 저장(purple, `capturedAt`). 각 신호당 점 하나 — 개수·대표 intent 색 폐기(2026-06-10, 캡처 intent 색과 마감 마커 색의 한 칸 충돌 제거). 카드 하단 범례와 1:1. **유일한 예외 — 기간 일정**(2026-06-10, `payload.endDate` 있는 schedule): 점 대신 시작~끝 칸을 가로지르는 **sky 막대**(점 레인과 별도 레인, 이어지는 쪽은 라운드 없이 옆 칸과 연결). 하루짜리 일정은 그대로 점 — 겹치는 기간들은 하나의 연속 막대로 합쳐 보인다(범례는 점 3종 유지, 막대는 일정과 같은 sky 라 별도 항목 없음).
2. **날짜 탭** — 그날 캡처 + 그날 마감/일정 항목을 sheet 로 함께 표시(기간 일정은 시작~끝에 걸친 모든 날의 「일정·마감」에 포함). sheet 셀 탭은 sheet 를 닫지 않고 그 위로 상세를 hero present (닫으면 보던 목록 복귀). sheet 내 수정(상세 편집·완료)은 재탭 없이 즉시 반영된다(2026-06-15 — `repositoryChanged` 시 선택 날짜 목록 재조회). sheet 헤더의 **"+ 일정 추가"** → 간단 폼(제목 + 선택 시간, 날짜는 그날 고정) → `appCalendar` channel 로 confirmedInstances schedule 직행 생성(채팅 일정 확정과 같은 경로) + 시스템 캘린더 등록. 저장 즉시 그날 목록·점에 반영(2026-06-15).
3. **하단 리스트** — ① 다가오는 일정(active schedule, 시작 빠른순 — 기간 일정은 시작이 지났어도 끝이 안 왔으면 "진행 중"으로 포함, 라벨은 "시작 ~ 끝"으로 **양끝 동일 절대 포맷**("M월 d일 (E)" + 시각 있으면 덧붙임 — 한쪽만 상대 "D-10"으로 적어 끝의 절대 날짜와 포맷이 어긋나던 문제 수정)) ② 마감 임박한 할 일(미완료) ③ 완료한 일. ①②③ 모두 **기본 3개 + "N개 더 보기"↔"접기" 인라인 토글**(`CollapsibleRows`, 2026-06-19). ①② 행은 **카드 박스 제거 → 플랫 + 행 사이 1px 디바이더**(ink300/0.5), 할 일 체크박스 탭 타겟 44pt(일정 날짜 타일과 행 높이 통일). 날짜 탭 sheet 의 「일정·마감」/「저장한 기억」도 같은 더보기(행은 `DayMochiRow` 카드 유지). 많이 쌓여도 세로로 끝없이 나열 안 됨.
4. **할 일 체크박스** — `active ↔ archived(todoCompleted)` 토글, 서버 `POST .../lifecycle` 로 영속(낙관적 로컬 + 서버 push, 실패 시 롤백). 같은 화면 중복 캡처(같은 제목·라벨·마감)는 **표시에서 하나로 합치되**, 숨은 쌍둥이 instance 도 완료 토글에 함께 전이된다(하나만 완료하면 쌍둥이가 되살아나는 혼란 방지). 도메인 데이터는 합치지 않는다.

### 3.7 백탭 Snippet 카드 + 메모 모달 + 온보딩 검증

**snippet 카드** (`BackTapResultSnippet` wrapper, 외부 앱 위 표시 — 일반 캡처 분기는 `.capture` → `BackTapSnippetView`, 온보딩 검증 분기는 `.verified` → `BackTapVerifiedSnippetView`).

`CaptureScreenshotIntent` 가 `Take Screenshot → 이미지 변환(PNG)` 출력을 받아 PNG 한 장을 `pending-backtap/<captureID>.png` 에 stash 한 직후 `.result(view:)` 로 반환. 시스템이 `ShowsSnippetView` 메커니즘으로 카드를 외부 앱 위에 띄움 — **모찌 앱을 깨우지 않는다** (Papago 패턴). 카드 구성:

- 한 줄 안내 "이 화면을 어떻게 저장할까요?" + 작은 모찌 아이콘
- 두 버튼: **캡쳐** (`CommitBackTapCaptureIntent`) / **메모** (`OpenBackTapMemoIntent`)

**캡쳐 분기** — `CommitBackTapCaptureIntent` (`openAppWhenRun = false`):
- background 에서 pending → 영구 `captures/<captureID>.png` 로 이동 + sha256 계산 + Realm `MochiItem(channel: .screenshot, syncState: .pendingUpload)` upsert + pending PNG 폐기
- **백엔드 ingest 시도 안 함** — snippet background process 는 `AppDependencies.bootstrap()` 미호출 상태일 수 있어 인증/네트워크 인프라 부재 가능. Realm 에 박아둔 `.pendingUpload` 가 안전. 다음 모찌 active 시점에 `MochiItemSyncWorker` 가 ingest 시도 (실패 시 1회 더 retry 후 `.syncFailed` marking — 자동 재시도 종료, 사용자 retry UI 필요, 현재 TODO)
- snippet 카드 자동 dismiss. 외부 앱 그대로.

**메모 분기** — `OpenBackTapMemoIntent` (`openAppWhenRun = true`):
- pending PNG 즉시 폐기 (사용자가 스크린샷 의도가 아님을 명시한 것)
- `pending-backtap/<captureID>.memo` marker 파일 stash
- 모찌 앱 foreground 진입 → `RootFeature` 가 marker 발견 → `BackTapModalFeature` 풀스크린 모달 (`ultraThinMaterial` blur + 모찌 캐릭터 + textarea + 저장 버튼)
- "저장" → `commitMemo` 가 Realm `MochiItem(channel: .appDirectInput, text:)` upsert + `POST /api/v1/mochi_items` 시도 (모찌 앱 안이라 인프라 정상). 실패 시 fallback 은 `MochiItemSyncWorker`.
- "취소" → marker 폐기 + dismiss.

**invariant**:
- `.png` 는 두 commit intent 중 하나가 실행되면 폐기 (캡쳐 분기는 commit 직후, 메모 분기는 marker stash 직전).
- `.memo` marker 는 모달의 어느 정상 분기 (저장/취소) 든 폐기.
- snippet 시스템 dismiss (사용자 외부 탭 / timeout) 후 잔재 (`.png`) 는 `RootFeature` 가 launch / scenePhase active 시점에 sweep.

**온보딩 검증 모드** (일반 캡처 흐름과 분리된 1회성 셋업 절차 — §3.3 단계 ②의 3번째 스텝 "실동작 검증"):

온보딩이 "지금 백탭 해보세요" 단계에 들어가면 `BackTapVerificationClient.begin()` → `AppGroup.beginBackTapVerification()` 이 App Group 파일 마커 `pending-backtap/verify.active` (TTL 120s) 를 연다. 이 창이 열린 동안:
- **진짜 저장을 하지 않는다.** 백탭이 도달하면 진입점이 `AppGroup.markBackTapVerificationHit()` 만 호출 (`verify.hit` 기록 + `verify.active` 즉시 소비) 하고 스크린샷 PNG·`MochiItem` 을 만들지 않는다 — 검증용 백탭이 쓰레기 캡처로 메모리를 오염시키고 잘못된 동작을 학습시키는 것을 막는다.
- **진입점은 두 경로 모두 hit 을 찍는다.** snippet 경로 `CaptureScreenshotIntent` (→ "백탭이 작동해요!" 카드) 와 ShareExtension 경로 `ShareExtensionPrincipal` (→ `BackTapVerifyShareView`). 사용자 단축어가 어느 경로로 흐르든 검증된다.
- **모찌가 폴링해 먼저 알린다.** 온보딩이 `verify.hit` 존재를 폴링(90초 타임아웃), 도달을 감지하면 체크리스트를 완료 처리한다 (미션 "떠오른다" — 사용자가 확인 버튼을 누르는 게 아니라 모찌가 먼저 안다). 감지·타임아웃·단계 이탈 시 `end()` 가 마커를 비운다.

검증은 1회성이라 hit 직후의 일반 백탭은 다시 정상 저장 흐름으로 돌아간다. App 타겟이 `.live` 를 주입하지 않거나 사용자가 단축어를 연결하지 않으면 검증은 감지되지 않고 "나중에 할게요"(skip)로 진행한다 — 의도된 안전 기본값.

### 3.8 모찌 상세

"검수"가 아니라 "회수" — 분류 라벨을 나열해 검수시키지 않고, 다시 알아보고 바로 행동하게 한다 (PRODUCT §1.5 미션·§8 UX 원칙).

구성(정보 위계, `DetailView`). **어떤 intent·source·payload 조합을 열어도 골격이 같다**(2026-06-11) — 출처·시간 eyebrow 가 항상 첫 텍스트 줄, 섹션 라벨은 카드 밖에 노출, ③의 행들은 단일 행 문법(leading 타일/체크 + 제목 + 부제 + 독립 흰 카드)을 공유한다. 의도별 차이는 행의 *내용*으로만 드러난다:
1. **회수 헤더** — hero(시각 회상) + 출처·시간 eyebrow + 정체성 제목(연필 아이콘 탭 → 인라인 교정, 로컬 `userTitle` 오버라이드). hero 는 스크린샷이면 캡처 이미지(세로=center fill / 가로=fit+blur, **카드 풀폭**), 메모·URL 이면 정체성 색 밴드(메모=버터/크림, URL=보라)로 **빈 흰칸 없이 풀폭**을 채운다(2026-06-15 — 이전엔 메모·URL 헤더가 비어 좌우 흰 여백). 분석중 상태도 **같은 hero 렌더러**(`ScreenshotPreviewImage`/`DetailIdentityHero`)를 써 분석이 끝나도 이미지가 튀지 않는다. eyebrow 를 제목 위에 두어 어떤 조합을 열어도 같은 첫인상을 갖는다
2. **헷갈려요 배너** — needs_review=true 일 때만, 후보 칩 + "다른 의도"(자연어 재분석)
3. **지금 할 수 있어요** (섹션 라벨 노출) — 분류를 라벨이 아니라 *형태*로, **캘린더 탭과 같은 시각 언어**(2026-06-11 정합): 할 일=체크 토글(완료↔미완료 양방향, 완료는 strikethrough 로 아래에 남음) + 할 일 이름(`payload.title`) + D-day 라벨(마감 시각이 있으면 "오늘 마감 · 오후 9:00"처럼 덧붙임 — todo 시각은 deadline 안에 담김), 일정=날짜 타일(월/일) + 일정 이름 + 상대 라벨(오늘/내일/요일/D-n + 시각, 기간 일정은 "시작 ~ 끝"), 링크=보라 타일 + "원본에서 보기"(host 부제) 행 — 그라데이션 CTA 폐기, 같은 행 문법으로. 의도가 여럿이면 행이 여럿, 하나도 없으면 섹션 숨김. 토글은 캘린더 탭과 공용 경로(낙관 반영 + 서버 push + 레거시 치유/롤백, `TodoLifecycleSync`)
4. **관련 링크** (섹션 라벨 노출, 2026-06-15 — Agent ResourceFinder `referenceLinks`) — 캡처가 가리킨 상품·장소·자료를 모찌가 찾아 **메타 행카드**(브랜드 favicon 타일 + provider 이름 + 제목 + "업종·지역/요약문/브랜드" 부제·쇼핑 가격 한 줄)로, usefulness 5 는 "딱 맞아요" 뱃지. 탭 → 지도·예약·구매·리뷰 링크. 결과 없으면 섹션 숨김 — 회수의 능동 주체를 모찌로(PRODUCT §1.5 미션). 이전 `shoppingProductQuery` 기반 "쿠팡·네이버 검색" 행을 대체한다(ResourceFinder 가 쇼핑 검색 URL 도 함께 생성). 카드 변형 A~E 비교 끝에 **메타 행카드(D)** 확정(2026-06-15)
5. **모찌가 정리했어요** (섹션 라벨 노출) — AI 요약(제목과 다른 정보) + 원본(텍스트 인용·내 메모 카드)
6. **비슷한 기록** (섹션 라벨 노출, 2026-06-13 구현 — `DOMAIN_DESIGN.md` §10.5) — 의미가 가까운 다른 기록을 가로 캐러셀로(`RecentMochiCard` 재사용, `HomeDesign` 토큰). 카드마다 "왜 비슷한지" **근거 칩**(같은 출처 / 비슷한 종류) — 단순 유사 리스트가 아니라 *이래서 떠올렸다*를 보여 **회수의 능동 주체를 모찌로** 둔다(PRODUCT §1.5 미션). 임계값 미달로 비슷한 게 없으면 **섹션 자체를 숨긴다**(약한 추천으로 신뢰를 깎지 않는다). 카드 탭 → 그 상세를 **앞으로 push**(오른쪽 슬라이드, 시스템 back·엣지 스와이프로 이전 상세 복귀 — A→B→C 로 계속 타고 들어가도 스택으로 쌓여 길을 잃지 않는다, 2026-06-15 hero 교체→push 전환). ※ 검색탭 §3.5 의 semantic "비슷한 기억"과는 **다른 개념** — 그건 query→결과 매칭, 이건 item→이웃 자동 회수

("더 자세히" 접힘 섹션은 2026-06-10 제거 — 추출 정보·태그·근거는 회수에 기여하지 않는 내부 디테일이라 노출하지 않는다.)

**우상단 ⋯ 메뉴**(2026-06-14): `[즐겨찾기 추가/해제(star)] · [이미지 저장(square.and.arrow.down, 이미지 있을 때만)] · [삭제]`. 즐겨찾기는 "사용자가 모찌에게 준 중요 신호" — 토글 시 낙관 반영 + 서버 push(`POST /mochi_items/{id}/favorite`, 실패 시 `FavoriteSync` 롤백). 이미지 저장은 원본 풀해상도를 사진 앱에 저장(로컬 캐시 우선, 없으면 presign 다운로드 → 저장 후 "사진에 저장했어요" 토스트). 검색 카드(§3.5) 컨텍스트 메뉴에도 같은 즐겨찾기 토글이 있다.

분류(4-Intent)는 사용자에게 검수용 라벨로 노출하지 않는다 — 화면에는 행동(체크/통지/열기)으로만 드러낸다 (정본: PRODUCT §5 "노출 원칙 — Intent 는 배관이다"). 미확신(needs_review) 시에만 "헷갈려요"로 확인을 청한다.

**진입 전환**: 카드(홈·캘린더 sheet) → 상세는 UIKit 커스텀 **hero(zoom) present** — 카드 frame 을 캡처해 비행 경로를 지정하고, 비행 중 상세 썸네일을 숨겼다 드러낸다. path push 아님. 헤더 아래 섹션들(배너·행동·정리)은 비행과 겹쳐 `riseIn` 시차 등장 — 헤더(비행 착지 지점)는 움직이지 않는다. **단 상세 안의 '비슷한 기록' 탭은 hero 가 아니라 그 상세가 소유한 `NavigationStack` push**(자식 상세를 앞으로 쌓고 시스템 back·엣지 스와이프로 복귀, back·바 버튼 tint=모찌 퍼플, 2026-06-15). **닫기 동작은 방향으로 갈린다** — root 진입은 hero 비행, 그 위로 **가로 엣지 스와이프/back = 한 칸 뒤로**, **세로 아래 드래그 = 깊이 무관 스택 전체 종료(→홈)**. 깊이 들어간 뒤 back 반복 없이 한 번에 빠져나오는 길이며(자식 ⋯ 메뉴의 '닫기'가 명시적 보조), 자식 위에서의 전체 닫기는 hero 없이 fade. 닫기(X)는 root 상단에만(자식은 시스템 back). 알림으로 다른 상세를 열 땐 현재 상세를 닫고 그 항목으로 교체하며(push 스택도 리셋), 교체 중 닫힘↔열림 경합으로 화면이 '투명한데 먹통' 되던 문제를 해소했다(`ZoomDetailPresentation` 의 dismiss/present 직렬화, 2026-06-15).

### 3.9 Share Extension

콘텐츠별 처리:

| 입력 타입 | 처리 경로 |
|---|---|
| 이미지 | 스크린샷 분석 |
| 텍스트 | 메모 분석 |
| 링크 | WebFetch 후 분석 |
| 선택 텍스트 + URL | 텍스트와 링크 통합 분석 |

UI (`ShareEntryView` / `BackTapShareView`, 토큰은 `ShareDesign`) — 콘텐츠에 따라 2가지 레이아웃:
- **이미지 우세 모드** (이미지만): 탑바(취소 + 출처 칩 + "사진 빼기" 필) + 첫 이미지 **전체 fit 미리보기**(`ShareCropImage`) + 추가 이미지 개수 + 메모 필드(compact) + 저장
- **텍스트/URL 우세 모드**: 탑바 + Preview 카드(URL host 강조·텍스트 인용·이미지 개수) + 메모 필드(펼침) + 저장

**이미지 미리보기 + 인라인 크롭** (`ShareCropImage`): 캡처를 **자기 비율 그대로 카드가 꽉 감싸**(주변 배경 박스·레터박스 매트 없이) 한눈에 100% 를 보인다 — 이전 폭맞춤 + 세로 스크롤이 "창처럼 일부만" 보여 잘린 것으로 오해되던 문제를 없앤다(상태바 자동크롭도 제거). 그 위에서 **네 모서리 L 핸들**로 그 자리에서 크롭한다: 전체 이미지는 항상 보이고 크롭은 선택 사각형이라 **모서리를 안쪽으로 끌면 축소·바깥(이미지 경계까지)으로 끌면 확대** — 양방향 자유, 원본으로 되돌아가지 않는다. **잘려나갈 영역은 항상 dim 오버레이로 덮여** 정지 중에도 "이렇게 잘린다"가 예측되고, 드래그 중엔 dim 이 짙어지며 3분할 그리드가 뜬다(진입·확정 햅틱). "원본" 칩으로 언제든 전체 복원, "모서리를 끌어 자르기" 힌트. 크롭은 제출 시 `ShareImageCropper` 가 App Group 파일에 실제 적용해 새 `ImageRef` 로 교체하므로 **백엔드 계약(이미지 1장=1 ref)·멱등키는 불변**. "사진 빼기"(메모만 남기기)는 코너 핸들과 자리가 겹치지 않게 탑바로 올렸다. 다크모드는 `ShareDesign` 듀얼 토큰으로 전 표면 지원.

메모 필드(`userMemo`, "추가 메모가 있으면 알려주세요")는 분류 시 화면보다 우선하는 1차 의도 증거로 쓰인다 (DOMAIN_DESIGN §3).

### 3.10 분석 진행·완료 피드백 — Live Activity + 알림

캡처 후 분석이 끝난 것을 앱을 열지 않아도 알게 한다. **회수의 능동 주체는 모찌** (PRODUCT §1.5).

**Live Activity — needs_review 전용** (팀 결정 2026-06-09, 진행중/완료 LA 폐기):
- iOS 가 LA 를 직접 시작하지 않는다. **needs_review=true 분석완료 시 백엔드가 push-to-start** 로 background(잠금)에서 LA 를 시작하는 단일 경로 (iOS 17.2+, `la_start` 토큰).
- content-state phase: `.ready`(후보 2~3개 버튼 — **한 탭 선택이 1급 인터랙션**, 앱을 열지 않고 Lock Screen 에서 의도 확정 + "다른 의도"는 앱 진입) → 사용자가 후보를 고르면 위젯이 `reanalyze`(hint=후보)를 직접 호출하고 로컬에서 `.confirmed` 로 전이.
- **전 채널** (스크린샷·링크·텍스트). 확정(needs_review=false)·실패 분석완료는 **푸시하지 않는다**(2026-06-17, 저장완료 알림 제거 — 조용히 저장; foreground SSE·폴링·복귀 reconcile 이 반영). needs_review=true 만 LA push-to-start + alert. 알림 탭 → 홈 탭 + 해당 기록 상세로 바로 진입(server→local 역매핑; 다른 상세가 떠 있으면 닫고 그 항목으로 재open, 같은 항목이면 유지).

**알림 (헷갈려요 = needs_review=true 일 때만, 2026-06-17~)** — 확정 저장완료("이렇게 저장했어요")는 더 이상 푸시하지 않는다(조용히 저장; foreground SSE·폴링·복귀 reconcile 이 반영). 빈도 조절은 OS 알림 설정에 맡기고 모찌가 가르지 않는다. 본문은 iOS 가 truncate 하므로 **요약 1줄**:
- 헷갈려요: "어떤 의도로 남겼나요?" (탭 → 앱, 홈 "지금 확인해 주세요" 버킷으로). **일반 alert 다 — interactive notification 은 채택하지 않는다**(의도 선택은 Live Activity / 앱 내 버킷이 담당).

**실시간 분담**:
- foreground = **SSE 즉시 반영** + **3초 폴링 fallback** + **완료 푸시 즉시 reconcile**(앱 active 일 때 완료 알림을 받으면 폴링 tick 을 기다리지 않고 그 항목을 바로 가져온다, 2026-06-15). 셋 다 결과를 Realm 에 쓰면 `observeChanges` 로 홈·캘린더·**열어둔 상세**가 함께 갱신된다 — **분석중 상세를 열어둔 채 완료되면 화면이 자동으로 완료 뷰로 전환**(항목별 폴링은 분석 반영 시 자동 종료).
- background/종료 = **APNs** (LA push-to-start + 완료 알림). SSE 는 background 에서 소켓이 끊기므로 이 구멍을 APNs 가 메운다.
- 앱 복귀 시 reconcile — background 중 놓친 상태를 1회 동기화.

**always-on fallback**: 알림 권한을 거부하거나 푸시를 놓쳐도, 홈의 **"지금 확인해 주세요" 버킷**(§3.4)이 진실원천이라 헷갈려요 처리는 언제든 앱 안에서 가능하다.

**실패/지연 fallback**: lifecycle `failed` 또는 분석 90s 초과 시 `demoteToManual` → "헷갈려요(의견 없음)" + 직접 분류 + "다시 맡기기"(`requeueForAnalysis`). webFetch 실패 등으로 인한 무한 폴링을 차단하고, 분석이 죽어도 항목이 사용자 손에서 벗어나지 않게 한다.

### 3.11 능동 회수 — 모찌가 먼저 떠올려준다

"다시 볼 가치 있는 기억을 모찌가 먼저 떠올려준다." **회수 = 분류가 아니다** — category 통계·주제 묶음 라벨은 회수 화면에 노출하지 않는다(리마인더이지 회고가 아님). 회수의 능동 주체는 사용자가 아니라 모찌(PRODUCT §1.5 미션). cold start 빈손은 결함이 아니라 정상(리마인드할 게 없으면 안 보여주는 게 옳다). **3단 구조**(`RecallFeature` / `RecallView`):

**① 홈 "회수 한 칸"** (§3.4-4, `HomeFeature` slice) — 고정 자리·고정 틀. "다시 보면 좋을 기억 N개" + **가장 가치 높은 1개 미리보기 한 줄**(안 눌러도 떠오르게). 비면 "지금은 없어요"로 채워 레이아웃이 출렁이지 않게(미션 "앱 켜면 바로"). needsReview 다음 상단 배치. 회수=가변이라 별도 화면을 갖지 않고 홈엔 요약(count + top-1)만 둔다. 탭 → ②.

**② 자세히 보기** (`RecallListFeature`) — **통일 카드 목록**(썸네일=실제 캡처 이미지 + 이유 칩 + 제목 + 한 줄 + 시점). 지식/관련/맥락이 모두 같은 틀 — 묶음은 "관련 기억 N개"만 덧붙이고 **카테고리로 승격하지 않는다**(분류로 안 읽히게). 카드 탭 → ③.

**③ 기록 상세** (`RecallDetailFeature`) — `kind`(=`outbox.kind`, plan_kind 유래)별로 섹션을 다르게 렌더, **kind마다 별도 화면을 만들지 않는다**:
- **지식**(`spaced`): 모찌가 정리한 핵심 + 원본 링크(원본 대체 금지).
- **관련·맥락**(`recall`): 관련 기억 목록(그때 맥락) + "왜 지금 이어지는지" 연결 설명. 관련 N개(`related`, 탭 → 그 항목 상세)를 상세가 품는다(트랙 C 구현됨 2026-06-16, 정본 `tech-plan.md` §8 P7–P9). 표시·게이트는 서버 `relatedCount` 가 아니라 실제 렌더 가능한 `related.count` 기준.
- 단정 금지 — 항상 확인 질문 톤("샀나요"❌ → "결정하셨어요?"⭕).

**이유 칩 4종** ("왜 지금 떠올렸나" — 회수 신호의 표현이지 분류가 아니다, `RecallReasonKind`): **잊기 전에 한 번**(fadingValue) / **관련해서 여러 번**(relatedCluster) / **요즘 자주 보시던**(revisitedOften) / **지금 맥락과 이어져요**(linkedToRecent). 색·아이콘은 iOS 매핑(비계약).

**알림 landing** — 단건 회수 알림(routeType="detail" + `recallEventID`) 탭 → ③ 상세 직행(기존 `mochiItemID`/`sourceIntentID` deep-link 재사용, server→local 역매핑). **로컬 역매핑 실패 시 `recallEventID`로 서버 fetch fallback**(`GET /recall/events/{id}`, 빈 상세 금지). 진입 경로(App 레이어): `MochiAppDelegate` → `RootFeature` → `MainTabFeature` 가 ③ 회수 상세 push. 홈 한 칸은 알림이 아닌 in-app 진입.

**응답 액션** — primary 는 **사용자 목적 수행**(열기·원본 보기·완료)이지 "모찌 품질 평가"가 아니다(미션 정합 — "필요한 기억은 *떠오른다*"). 학습은 행동 신호(open/탭 진입 = `opened`)를 우선으로 삼고, 명시 피드백은 보조/dismiss 사유로 낮춘다. 액션 ↔ 서버 reaction 1:1: **기억났어요/탭 진입/열기** = `opened`(spaced+knowledge 면 instance 소생) · **원본 보기** = 원본 mochiItem 상세 · **그만 보기** = `stop`(destructive — primary confirm 과 시각 분리). reaction 보고는 `POST /recall/events/{id}/reaction`. **"그만 보기"는 토스트 확인과 함께 그 카드를 홈 회수 히어로에서도 제거**한다(opened-close 의 `recallDetailClosed` 재사용 — "그만 보겠다"는데 화면에 남으면 미션 위반, 2026-06-21). 서버도 영구 억제해 재출현 없음: 트랙 A 는 plan cancel, **트랙 C(plan 없는 직행)는 sent outbox 행을 종결(skipped)** — 안 그러면 피드가 `dismissed_at` 을 무시해 앱 재시작마다 부활(`DOMAIN_DESIGN.md` §3).

**접근성**: 이유 칩은 VoiceOver 에서 "회수 이유: 잊기 전에 한 번"처럼 의미가 읽히게 라벨링(색·아이콘만으론 불충분). 홈 한 칸 preview 는 Dynamic Type 확대 시 2줄까지 확장(레이아웃 안정은 유지하되 텍스트는 안 자름). 상세 액션은 큰 글자에서 가로 버튼이 잘리면 세로 스택으로 전환.

> 발송 정책·스키마는 백엔드 — `DOMAIN_DESIGN.md` §3(notification_plan/outbox)·§5.4(종료 연동)·§5.2(소생), `ARCHITECTURE.md` §1·§3.4(Recall Worker 흐름). 화면 정본 소스는 `journal/proactive-recall/ux-ui.md`.
