# BUSINESS_MODEL — 모찌 수익모델 · LLM 원가 분석

> 목적: 가격·무료정책·통합크레딧 cap 을 **단위원가(실측) + 사용량/전환(가정)** 위에서 결정하기 위한 단일 분석 문서.
> 단위원가는 `llm_usage` 테이블 실측이라 신뢰 가능하나, **사용량·전환율은 가정**이고 가격은 아직 **미확정(draft)** 이다.
> 원가 구조가 바뀌면(모델 교체·media_resolution 도입 등) 이 문서와 `app/shared/llm_cost.py` 단가표를 함께 갱신한다.
> 🧮 **인터랙티브 시뮬레이터: [`docs/business-model-sim.html`](business-model-sim.html)** — 브라우저로 열어 변수(유저수·전환율·가격·무료정책·cap·단가)를 조절하며 월손익·LTV/CAC·손익분기를 실시간 확인. 오프라인 동작.

## 0. 데이터 근거와 한계 (먼저 읽을 것)

- 원가 수치는 **`llm_usage` 테이블**(migration 0021, 계측 시작 2026-06-13) 기준. 분석 시점 데이터는 **4일치(06-13~16), 사용자 6명, 그중 1명이 전체의 82%** — 즉 **실사용자가 아니라 팀 도그푸딩**이다.
- 따라서 **절대 사용량(월 몇 건)은 대표성 없음.** 단, **단위원가(캡처 1건당·채팅 1건당)는 신뢰 가능**하고 가격책정에 필요한 건 이 단위원가다.
- 사용자 **캡처 중앙값은 총 14.5건**(도그푸딩 기간). 무료/유료 평균 사용량 추정의 유일한 실측 앵커.
- 전환율·리텐션은 **출시 전이라 데이터 없음** — 전부 가정. 의사결정 전 베타/A-B 로 검증 필요.
- 환율 가정: **₩1,380 / $1**.

## 1. 원가 구조 (실측)

### 1.1 사용 모델 단가 (확정 — `app/shared/llm_cost.py` + 웹 교차검증)

| 모델 | 용도 | 입력 | 출력 |
|---|---|---|---|
| **gemini-3.1-flash-lite** | 캡처 분석·채팅·분류 **전부** | $0.25 / 1M | $1.50 / 1M |
| voyage-3-large | 임베딩(캡처당 1회) | $0.18 / 1M | — |
| rerank-2.5 | 검색 리랭크 | $0.05 / 1M (첫 200M 무료) | — |

- 현재 **모든 LLM 경로가 flash-lite 단일** (가장 싼 모델). 비용 최우선 전략(`config.py` 주석).
- Voyage 임베딩 청크는 평균 **21토큰**뿐 → 건당 $0.0000038, **사실상 0**. 리랭크도 무료티어 안.
- **→ 원가는 Gemini 가 99%+ 지배.** Voyage·검색 API(Naver/Tavily/YouTube)는 무시 가능 수준.

### 1.2 단위원가 (가격책정의 핵심)

| 항목 | 원가 | 비고 |
|---|---|---|
| **캡처 1건 분석** (+임베딩) | **$0.0040** | 입력 ~13.3k + 출력 ~0.43k 토큰. 약 250건당 $1 |
| **채팅 1대화** (평균 3턴) | **$0.0127** | 캡처의 **3.2배** |
| 채팅 1 LLM 콜 | $0.0043 | |

- 입력 토큰이 압도적(전체 2.4M in vs 0.11M out). 캡처 1건당 입력 p50 ≈ **15,270토큰**.
- 한 호출 입력 15k 중 **이미지는 일부**(1920px ≈ 1.5~2k 토큰 추정), 나머지는 **시스템 프롬프트 + 함수콜 툴 스키마**가 차지 → 이미지 추가 다운스케일 ROI 낮음 (§6).
- **부가 버퍼 ×1.15**: 프로필요약·주간digest·회수planner 는 현재 `llm_usage` 에 미계측 → 추정 비용에 15% 버퍼 적용.

### 1.3 인프라 고정비

- 현재 **$50/월** (서울 e2-small + e2-medium + 디스크 + static IP, `docs/INFRA.md`).
- 사용자당 분담은 규모가 좌우: 6명 $8.3/명 → 1,000명 $0.05/명 → **100명 넘으면 LLM 이 지배적 변동비**.
- 10k 규모 추정: 유료 1,000명 + 신규 체험 트리클 → 약 **$120~300/월** (인스턴스 복제·DB 상향·GCS 저장 증가 포함, 미정밀).

## 3. 요금 모델 — 결정/미결정

### 3.1 결정된 것

1. **통합 크레딧 모델 ✅** — 캡처/채팅을 따로 세지 않고 단일 월 예산으로. **캡처 = 1크레딧, 채팅 = 3크레딧**(실비 3.2배를 3으로 — 약간 후하나 worst-case 도 안전, §4.3). 어느 쪽으로 쓰든 최악 COGS 가 한 숫자로 고정.
2. **무료 = 평생 일회성 체험 ✅** — *지속* 무료 티어가 아니라 **사용자당 평생 N건** 체험. 소진 후엔 유료 전환 안 하면 캡처 중단 → **무료의 지속 원가 0** (일회성 CAC 로만 발생). §4.1 비교 참조.
3. **앱스토어 소규모 사업자 수수료(15%) 추구** — 30% 대비 손익이 크게 갈림. 전제로 둔다.

### 3.2 미결정 (deliberation 중)

| 항목 | 후보 | 비고 |
|---|---|---|
| 체험 한도 | 50 vs **100~150** | 원가가 미미해 "비용"이 아니라 "전환(아하 모먼트 도달)"이 기준. §4.2 |
| 유료 가격 | ₩3,900 vs **₩1,900** | ₩1,900 은 전환 3배 필요 — §5.2 |
| 유료 월 cap | 가격 연동 | ₩3,900→~500크레딧 / ₩1,900→~200크레딧. §4.3 |

## 4. 핵심 분석

### 4.1 무료: 평생 체험 vs 지속 무료 (왜 체험을 택했나)

전환 10% · 1만명 · 수수료 15% 기준 **월손익** 비교:

| 무료 모델 | 월손익 | 성격 |
|---|---|---|
| 지속 무료 1캡/일(30/월) | −$24 ~ +$468 (휴면률 의존) | 본전 수준 + UX 나쁨(일일 하드캡) |
| 지속 무료 총 50/월 | −$845(전원 꽉) ~ +$386(평균20) | UX 좋으나 원가 변동 큼 |
| **평생 체험 50건** | **+$1,387** + 일회성 CAC $2,280 | **지속 원가 0, 압도적** |

**평생 체험은 무료가 매달 새는 비용이 아니라 일회성 획득비**라 정상상태 손익이 가장 건강하다(전환 5%에서도 흑자). 트레이드오프: 무료 거주자가 없어 **입소문·top-of-funnel 약화**.

### 4.2 체험 한도는 "비용"이 아니라 "전환"이 정한다

- 평생 체험 1인 일회성 비용: **50건 = $0.228, 100건 = $0.456, 150건 = $0.68** — 전부 월이익($1,387)에 비하면 푼돈.
- **즉 한도를 늘리는 비용은 거의 0.** 한도는 원가 방어가 아니라 **누적·회수 가치를 체감시켜 전환을 극대화하는 지점**으로 정해야 한다.
- **모찌 특유 리스크**: 가치가 "쌓일수록 회수가 떠오른다" 라 **누적이 있어야 체감**된다. 50건은 회수의 진짜 가치를 경험하기 *전*에 벽에 막힐 수 있어 전환을 떨어뜨릴 위험 → **권장 100~150건 또는 "건수 + 기간" 혼합.**

### 4.3 유료 cap — 가격에 연동, worst-case 방어용

cap 의 역할: **상한까지 꽉 쓴 유저가 적자 나지 않게** 하는 안전판. 평균 유저는 cap 한참 아래라 어차피 흑자.

손익분기 cap (수수료 15%):

| 가격 | 순매출 | **손익분기 cap** | 권장 cap (버퍼) |
|---|---|---|---|
| ₩3,900 | $2.40 | ~527크레딧 | ~500 |
| **₩1,900** | $1.17 | ~257크레딧 | **~200** |

**₩1,900 / cap 200크레딧** worst-case 마진: 수수료 15% **+22%**, 30% +5%. (전부 꽉 써도 흑자.)
- 200크레딧 = 캡처 200, 또는 캡처 140 + 채팅 20, 또는 캡처 110 + 채팅 30 등.
- 평균 유료유저 마진(₩1,900, 15%): 라이트 +76% / 미디엄 +52% / 적극 +24%.

## 5. 10k 사용자 손익 (평생 체험 모델)

### 5.1 일회성 획득비 (10k 전원 가입, 한 번만)

| 체험 소진 | 일회성 총비용 | 1인당 |
|---|---|---|
| 전원 50건 (최악) | $2,280 | $0.228 |
| 평균 30건 | $1,368 | $0.137 |

### 5.2 정상상태 월손익 (무료 지속비용 0, 인프라 ~$120)

**₩1,900 (수수료 15%, 유료 적극 100캡+30챗):**

| 전환율 | 유료수 | 월손익 |
|---|---|---|
| 5% | 500 | +$18 |
| 10% | 1,000 | +$155 |
| 15% | 1,500 | +$293 |

**₩3,900 (수수료 15%, 유료 적극 100캡+30챗):**

| 전환율 | 유료수 | 월손익 |
|---|---|---|
| 5% | 500 | +$634 |
| 10% | 1,000 | +$1,387 |
| 15% | 1,500 | +$2,141 |

### 5.3 ⚠️ ₩1,900 의 함정 — 전환 3배가 전제

- 유료 1인 순기여가 가격에 비선형으로 줄어든다(원가는 고정 차감): **미디엄(60+20)** 기준 ₩3,900 $1.84 → ₩1,900 $0.60(약 1/3), **적극(100+30)** 기준 $1.51 → $0.28(약 1/5).
- **₩1,900 이 ₩3,900 과 같은 총이익을 내려면 전환 약 3~5배 필요**(사용량 의존). 시뮬레이터 가격 슬라이더로 직접 확인.
- 구독앱 가격탄력성상 **반값으로 전환이 3배까지 뛰는 경우는 드물다**(보통 1.3~2배) → 그러면 ₩1,900 이 오히려 총이익을 떨어뜨림.
- 단 ₩1,900 은 **심리 임계(₩2,000 미만)** 효과 + **리텐션 개선** + **점유율 선점**의 전략적 가치가 있음. "전환↑를 이익이 아니라 성장지표로 본다"는 전제가 명확하면 합리적.
- **결정 전 베타/A-B 로 "전환 3배가 실제 나오는가"부터 검증.**

## 6. 원가 레버 (효과 순)

1. **전환율 ↑ + 전환 시점 ↓** (압도적) — 전환 +1%p ≈ 월 +$137(10k). 핵심가치(채팅·능동회수·검색)를 유료에 묶고 온보딩 직후 전환 유도. LTV/CAC 는 전환까지 걸리는 시간에 민감(퍼널 3개월 4.4x ↔ 12개월 1.1x).
2. **유료 리텐션** — LTV 가 잔존 개월수에 선형.
3. **이미지 다운스케일은 건드리지 말 것** — iOS 가 이미 **1920px / JPEG q0.60** 로 줄여 업로드(`CaptureUploadImagePreprocessor.swift`). 백엔드는 `media_resolution` 미설정(Gemini 기본 타일링). 입력 15k 중 이미지는 일부라 더 줄여도 푼돈이고 **글씨 깨짐 위험만 큼**. (정 줄이려면 클라 다운스케일보다 백엔드 `media_resolution=LOW` 가 저장본 화질 손상 없이 분석 입력만 낮추는 정공법 — 단 ROI 작음.)

## 부록 — 원가 재현 (SQL)

`llm_usage` 로 최신 단위원가를 다시 뽑을 때 (svc/db 접근은 `docs/INFRA.md` §3):

```sql
-- 모델·소스별 토큰/비용
SELECT source, model, count(*) calls,
       sum(tokens_in) tok_in, sum(tokens_out) tok_out,
       sum(tokens_in)*0.25/1e6 + sum(tokens_out)*1.50/1e6 AS usd  -- flash-lite 단가
FROM llm_usage GROUP BY source, model;

-- 캡처 1건당 평균 (단위원가)
SELECT round(avg(t),2) avg_tok, round(avg(t)*0.25/1e6,5) usd_approx
FROM (SELECT mochi_item_id, sum(tokens_in+tokens_out) t
      FROM llm_usage WHERE source='capture' GROUP BY mochi_item_id) x;
```

단가의 단일 진실은 Vertex AI 공식 가격이며 청구서와 대조해 확정한다(`app/shared/llm_cost.py` 주석).
