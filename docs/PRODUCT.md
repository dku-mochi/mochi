# 모찌(MOCHI) — 서비스 설명

> Multimodal AI 기반 스크린샷·링크·기록 통합관리 에이전트
> 2026 SW중심대학 디지털 경진대회 / 팀 **세얼간이** (송준서·박세현·이용찬)

---

## 1. 서비스 개요

### 1.1 이름

**모찌(MOCHI)**

서비스명은 두 문장에서 가져온다:
- "뭐든지 찍어보세요."
- "이거 뭐였지?"

사용자가 캡처하거나 저장해둔 정보를 나중에 다시 찾고 활용할 수 있도록 돕는 AI 기록 관리 에이전트.

### 1.2 한 줄 소개

> 모찌는 스크린샷, 링크, 텍스트 메모를 AI 가 자동으로 분석해 일정·할 일·지식·기록으로 분류하고 다시 찾아주는 iOS 기반 멀티모달 기록 관리 앱이다.

### 1.3 핵심 가치

사용자는 이미 많은 것을 저장한다. 문제는 저장 이후다.

저장은 쉽지만, 다시 찾고 활용하는 것은 어렵다. 모찌는 이 문제를 다음 원칙으로 해결한다:

> **입력은 더 쉽게, 분류와 회수는 AI 가.**

### 1.4 컨셉 문장

> 모찌는 사용자가 저장한 정보를 단순히 보관하는 앱이 아니라, AI 가 기록의 의도와 생명주기를 이해해 다시 활용 가능한 지식으로 바꿔주는 iOS 기록 관리 에이전트다.

짧은 버전:

> 뭐든지 찍어보세요. 모찌가 기억하고 정리해드릴게요.

## 2. 문제 정의

### 2.1 사용자 문제

사용자는 일상에서 정보를 빠르게 저장하지만, 저장 위치가 여러 앱에 분산되어 있다.

- 유튜브 영상을 나중에 보려고 저장했지만 잊어버림
- 카카오톡으로 받은 링크를 다시 찾기 어려움
- 스크린샷은 많지만 왜 찍었는지 기억나지 않음
- 학교 과제를 캡처해두었지만 마감일을 놓침
- 메모·사진·캘린더·브라우저 북마크가 각각 따로 움직임
- 저장한 정보가 일정인지·할 일인지·학습 자료인지 사용자가 직접 분류해야 함

### 2.2 기존 도구의 한계

| 기존 도구 | 장점 | 한계 |
|---|---|---|
| 카카오톡 나에게 보내기 | 빠르게 저장 가능 | 시간순으로 쌓여 찾기 어려움 |
| 인스타그램 저장 | 콘텐츠 저장 쉬움 | 인스타 내부 콘텐츠에 한정 |
| 유튜브 나중에 볼 동영상 | 영상 저장 쉬움 | 영상 내용 기반 검색 어려움 |
| 사파리 책갈피 | 웹페이지 저장 가능 | 사용자가 직접 폴더 관리 필요 |
| iOS 사진앱 | 스크린샷 자동 보관 | 왜 찍었는지 맥락 파악 어려움 |
| 메모앱 | 자유롭게 작성 가능 | 분류와 회수는 수동 |

모찌는 이 문제를 **단일 입력 경로 + AI 자동 분류 + 자연어 회수** 로 해결한다.

## 3. 제품 목표

모찌의 제품 목표는 세 가지:

1. 사용자가 어떤 앱에서든 기록을 쉽게 저장할 수 있게 한다.
2. AI 가 기록의 의도를 파악해 자동으로 분류한다.
3. 사용자가 나중에 자연어로 기록을 다시 찾고 활용할 수 있게 한다.

### MVP 우선순위

| 우선순위 | 기능 |
|---|---|
| P0 | iOS 앱 로그인 (Apple / Google OAuth) |
| P0 | 온보딩 튜토리얼 (모찌 소개·백탭·공유 저장 안내) |
| P0 | 홈 화면 (요약 카드·최근 모찌·추천) |
| P0 | 백탭용 입력 모달 (메모 / 스크린샷) |
| P0 | Share Extension (이미지·텍스트·링크 수신) |
| P0 | 4-Intent 분류 (일정·할 일·지식·기록) |
| P0 | 모찌 상세 페이지 (AI 요약·원본·액션 후보) |
| P1 | 질문 화면 (자연어 RAG 질의) |
| P1 | 모찌들 캘린더 (날짜별 기록 탐색) |
| P1 | 검색 (키워드 + 의미 기반) |
| P2 | 알림 (일정·할 일 리마인드) |
| P2 | 캘린더 연동 (사용자 확인 후 일정 등록) |

## 4. iOS 플랫폼 전략

### 4.1 Share Extension 기반 입력

iOS Share Extension 으로 다음 콘텐츠를 받는다:
- 이미지 / 스크린샷
- 텍스트 / 선택 텍스트
- URL
- 일부 앱의 미디어 메타데이터

Share Extension 은 별도 프로세스로 실행되며, App Group + shared container + 서버 업로드 큐 설계가 필요하다.

### 4.2 백탭(Back Tap) 기반 입력

아이폰 뒷면을 두 번 또는 세 번 탭해 단축어 실행. 모찌는 시스템 레벨에서 직접 제어하지 않고 **사용자가 Shortcuts 를 등록하도록 안내** 한다.

> 앞으로 아이폰 뒷면을 빠르게 두 번 탭하면 모찌를 불러올 수 있어요.
> 아래 버튼을 누르면 단축어 등록을 도와드릴게요.

### 4.3 OAuth 로그인

- Apple 로그인 (프라이버시 친화)
- Google 로그인 (Google Sign-In for iOS)

## 5. 정보 분류 체계 — 4-Intent

모찌는 모든 기록을 4가지 Intent 로 분류한다.

| Intent | 설명 | 예시 | 생명주기 |
|---|---|---|---|
| **일정** (schedule) | 특정 시간에 발생하는 이벤트 | 내일 3시 팀 회의 | 시간 도래 후 완료/기록화 |
| **할 일** (todo) | 완료 여부가 중요한 작업 | 보고서 제출하기 | 완료 전까지 활성 |
| **지식** (knowledge) | 다시 학습·참고할 정보 | RAG 구조 설명 글 | 장기 보관, 시간 지나면 decay |
| **기록** (memo) | 맥락 보존이 중요한 메모 | 회의 내용, 감상, 일상 | 영구 보관 |

### Intent 별 처리

**일정**
- 날짜/시간 추출 → 캘린더 등록 후보
- 알림 후보 생성

**할 일**
- 작업명·마감일·우선순위 추정
- 체크리스트 생성, 홈 제안에 표시

**지식**
- 핵심 주제·요약·태그 추출
- 임베딩 저장, 자연어 검색 대상

**기록**
- 원본 맥락 보존, 간단 요약
- 날짜별 타임라인 저장

### 생명주기

모찌의 차별점은 "저장 시점" 뿐 아니라 "저장 이후" 까지 관리한다는 점:

- "내일 3시 팀 회의"는 회의 전에는 알림 중요, 회의 후에는 기록으로 전환
- "보고서 제출"은 완료 전 홈에 계속 제안, 완료 후 archived
- "RAG 구조 설명 글"은 시간 지나도 검색 가치, 장기 보관

## 6. 핵심 사용자 시나리오

### 6.1 시나리오 A — 첫 가입

1. 앱 실행 → 스플래시 → Apple/Google 로그인
2. 튜토리얼: 모찌 캐릭터 Fade In/Out 안내
3. 백탭 단축어 등록 안내
4. 공유 저장 안내
5. 캡처 기반 자동 정리 안내
6. 홈 진입

### 6.2 시나리오 B — 백탭으로 메모 저장

1. 아이폰 뒷면 두 번 탭
2. Shortcuts → 모찌 입력 화면 (full screen modal)
3. "메모" 버튼 선택 → text area 입력
4. 저장 → AI 가 Intent 분류 → 홈의 최근 모찌에 표시

**입력 예시**: "다음 주까지 발표 대본 수정하기"

**AI 결과**: Intent=할 일, 제목="발표 대본 수정", 마감 후보="다음 주", 액션="할 일 목록에 추가"

### 6.3 시나리오 C — 백탭으로 스크린샷 저장 (snippet 흐름)

1. 학교 LMS 과제 화면에서 백탭
2. 단축어가 현재 화면을 자동 캡처 + PNG 를 모찌 stash → 외부 앱(LMS) 위에 모찌 snippet 카드가 떠오름. **LMS 화면은 사라지지 않음** — 사용자 컨텍스트 보존.
3. snippet 카드의 "캡쳐" 버튼 탭
4. 카드만 사라지고 LMS 가 계속 보임. 백그라운드에서 모찌가 Realm `Capture(.pendingUpload)` 로 저장.
5. 다음에 모찌 앱을 열면 Inbox 에 새 캡쳐 표시 (분석 진행 중 → 완료 후 4-Intent 분류).

**입력 화면**: 학교 LMS 의 과제 마감 안내 페이지

**AI 결과**: Intent=일정, 제목="과제 제출", 마감 후보="다음 주 금요일 23:59", 액션="캘린더에 추가"

**Fallback**: snippet 의 `CommitBackTapCaptureIntent` 는 `openAppWhenRun = false` 라 background process 에서 실행될 수 있고, 그 시점에 인증/네트워크 인프라가 부재할 수 있다 — 따라서 백엔드 ingest 는 시도하지 않고 Realm `.pendingUpload` 로 박아둔다. 다음 모찌 active 시점에 `CaptureSyncWorker` 가 ingest 시도하며, 실패하면 `.pendingUpload` 한 번 더 retry 후 `.syncFailed` marking — 이후 자동 재시도 없음 (사용자 retry UI 는 별도 TODO).

**AI 결과**: Intent=할 일, 제목="운영체제 과제 제출", 마감일="2026-05-30 23:59", 출처="X-learning"

### 6.4 시나리오 D — 유튜브 링크 공유

1. 유튜브에서 공유 버튼 → 모찌 선택
2. Share Extension → URL 수신
3. 서버에서 WebFetch / YouTube 메타데이터 조회
4. 요약 → Intent 분류 → 지식 또는 기록으로 저장

| 영상 유형 | 분류 |
|---|---|
| LangChain Agent 강의 | 지식 |
| 게임 하이라이트 | 기록 |
| 과제 제출 방법 안내 | 할 일 |
| 행사 일정 안내 | 일정 |

### 6.5 시나리오 E — 자연어 질문

**질문 예시**: "지난주에 저장한 AI Agent 관련 자료 정리해줘."

1. 질문 탭 → 자연어 입력
2. Query 분석 → Hybrid Search → 관련 모찌 검색
3. WebFetch / Calendar / Todo Tool 호출 (필요 시)
4. AI 답변 생성 → 참고한 모찌 목록 표시

**응답 예시**:

> 지난주에는 AI Agent 관련 자료를 3개 저장했어요.
> 1. LangChain Agent 구조 설명 영상
> 2. Tool use 기반 RAG 아키텍처 글
> 3. 발표 대본 중 Agent loop 설명 메모
>
> 공통적으로 "LLM 이 직접 도구를 선택해 사용하는 구조"에 대한 내용이 많았어요.

## 8. 페이지별 기획

### 8.1 스플래시

- 파스텔 그라데이션 배경
- 모찌 캐릭터
- 카피: "뭐든지 찍어보세요. / 모찌가 기억해둘게요."

### 8.2 로그인

- 모찌 캐릭터
- Apple 로그인 / Google 로그인 버튼
- 약관·개인정보 동의

### 8.3 온보딩 튜토리얼

| 단계 | 내용 | CTA |
|---|---|---|
| 1 | 모찌 소개 | 다음 |
| 2 | 백탭 소개 | 단축어 등록하기 |
| 3 | 공유 저장 소개 | 다음 |
| 4 | 캡처 자동 정리 소개 | 시작하기 |
| 5 | 홈 이동 | 모찌 시작하기 |

전환: Fade In/Out. 모찌 캐릭터 중심, 텍스트는 한 번에 1~2 문장.

### 8.4 홈

전체 구조:
1. 상단 인사 + 알림/설정
2. 검색형 질문 입력 바 ("무엇을 찾고 있나요?")
3. 4-Intent 요약 카드 (일정·할 일·지식·기록 개수)
4. 중요 제안 ("모찌가 중요해 보여요")
5. 이번 주 모찌가 저장한 기록 (Intent 별 개수 + 키워드)
6. 최근 추가한 모찌 (썸네일·제목·출처·Intent 태그·시간)

**중요 제안 예시**:
- "내일 3시 팀 회의가 있어요"
- "마감일이 있는 과제 2개를 발견했어요"
- "최근 저장한 AI Agent 자료가 발표 내용과 관련 있어 보여요"

### 8.5 질문

챗봇 UI + AI 가 사용한 도구를 보여주는 구조.

**추천 질문 칩**:
- 지난주 저장한 자료 정리해줘
- 이번 달 할 일 알려줘
- AI Agent 관련 모찌 찾아줘
- 발표 준비에 필요한 기록만 모아줘
- 마감일 있는 것들 보여줘

**Tool 사용 표시** (사용자 친화 문구로 변환):

| 내부 Tool | 사용자 표시 |
|---|---|
| `vector_search` | 관련 기록 찾는 중 |
| `db_query` | 저장된 모찌 확인 중 |
| `web_fetch` | 링크 내용 확인 중 |
| `calendar_tool` | 일정 후보 확인 중 |
| `todo_tool` | 할 일 확인 중 |
| `summarizer` | 요약 정리 중 |

답변에는 반드시 근거 모찌를 표시한다.

### 8.6 모찌들

날짜 기반 탐색:
1. 월간 캘린더 (날짜별 저장 개수 + 대표 Intent + 썸네일)
2. 날짜 클릭 시 상세 sheet
3. 캘린더 밑 할 일 리스트 (마감 임박·미완료)

### 8.7 검색

- 검색창: "제목, 내용, 링크, 기억나는 말로 검색"
- 필터: 전체 / 일정 / 할 일 / 지식 / 기록 / 이미지 / 링크 / 메모 / 미확인 / 중요
- 결과 카드: 제목·요약·Intent·출처·저장일·하이라이트

### 8.8 모찌 상세

구성:
1. 제목 + Intent 태그
2. 원본 콘텐츠 (이미지 / 텍스트 / 링크 미리보기)
3. AI 요약
4. 추출된 엔티티
5. 액션 후보 (할 일 추가 / 알림 / 캘린더 등록 / Intent 수정)
6. 관련 모찌

### 8.9 백탭 Snippet 카드 + 메모 모달

**snippet 카드** (`BackTapSnippetView`, 외부 앱 위 표시).

`CaptureScreenshotIntent` 가 `Take Screenshot → 이미지 변환(PNG)` 출력을 받아 PNG 한 장을 `pending-backtap/<captureID>.png` 에 stash 한 직후 `.result(view: BackTapSnippetView(...))` 로 반환. 시스템이 `ShowsSnippetView` 메커니즘으로 카드를 외부 앱 위에 띄움 — **모찌 앱을 깨우지 않는다** (Papago 패턴). 카드 구성:

- 한 줄 안내 "이 화면을 어떻게 저장할까요?" + 작은 모찌 아이콘
- 두 버튼: **캡쳐** (`Button(intent: CommitBackTapCaptureIntent)`) / **메모** (`Button(intent: OpenBackTapMemoIntent)`)

**캡쳐 분기** — `CommitBackTapCaptureIntent` (`openAppWhenRun = false`):
- background 에서 pending → 영구 `captures/<captureID>.png` 로 이동 + sha256 계산 + Realm `Capture(channel: .screenshot, syncState: .pendingUpload)` upsert + pending PNG 폐기
- **백엔드 ingest 시도 안 함** — snippet background process 는 `AppDependencies.bootstrap()` 미호출 상태일 수 있어 인증/네트워크 인프라 부재 가능. Realm 에 박아둔 `.pendingUpload` 가 안전. 다음 모찌 active 시점에 `CaptureSyncWorker` 가 ingest 시도 (실패 시 1회 더 retry 후 `.syncFailed` marking — 자동 재시도 종료, 사용자 retry UI 필요, 현재 TODO)
- snippet 카드 자동 dismiss. 외부 앱 그대로.

**메모 분기** — `OpenBackTapMemoIntent` (`openAppWhenRun = true`):
- pending PNG 즉시 폐기 (사용자가 스크린샷 의도가 아님을 명시한 것)
- `pending-backtap/<captureID>.memo` marker 파일 stash
- 모찌 앱 foreground 진입 → `RootFeature` 가 marker 발견 → `BackTapModalFeature` 풀스크린 모달 (`ultraThinMaterial` blur + 모찌 캐릭터 + textarea + 저장 버튼)
- "저장" → `commitMemo` 가 Realm `Capture(channel: .appDirectInput, text:)` upsert + `POST /api/v1/captures` 시도 (모찌 앱 안이라 인프라 정상). 실패 시 fallback 은 `CaptureSyncWorker`.
- "취소" → marker 폐기 + dismiss.

**invariant**:
- `.png` 는 두 commit intent 중 하나가 실행되면 폐기 (캡쳐 분기는 commit 직후, 메모 분기는 marker stash 직전).
- `.memo` marker 는 모달의 어느 정상 분기 (저장/취소) 든 폐기.
- snippet 시스템 dismiss (사용자 외부 탭 / timeout) 후 잔재 (`.png`) 는 `RootFeature` 가 launch / scenePhase active 시점에 sweep.

### 8.10 Share Extension

콘텐츠별 처리:

| 입력 타입 | 처리 경로 |

## 10. 비기능 요구사항

### 성능
- 홈 첫 로딩: 2초 이내
- 메모 저장 응답: 즉시 저장 후 비동기 분석
- 이미지 분석: 비동기 처리
- 질문 응답: 5~10 초 이내
- Share Extension 저장: 사용자가 오래 기다리지 않도록 큐 처리

### 보안
- OAuth 기반 인증 (JWT RS256)
- 이미지 URL private access
- 사용자별 데이터 격리
- 민감한 원본 데이터 암호화 고려

### 개인정보
- 사용자가 원본 삭제 가능
- AI 분석 결과 수정 가능
- 데이터 내보내기 가능
- 계정 삭제 가능
- AI 분석에 어떤 데이터가 사용되는지 안내

### 접근성
- Dynamic Type 대응
- VoiceOver label 제공 (아이콘 탭 포함)
- 색상만으로 Intent 구분하지 않기
- 충분한 대비
