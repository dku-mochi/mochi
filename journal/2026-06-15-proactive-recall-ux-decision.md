# 능동 회수 UX 설계 — "회수는 분류가 아니다"에 이르기까지 (2026-06-15)

> 코드 변경: `RecallHomeFeedMock.swift`(회수 3단 플로우 preview, 빌드 의존성 0) + 구버전 `ProactiveRecallHomeMock.swift` **삭제**(일원화). 프로덕션 백엔드/선행 문서 정합 반영은 아직(§6). 이 journal의 가치는 결과물보다 **결정이 무너진 순서**다.

---

## 0. TL;DR

선행 journal에서 트랙 C "주제 묶음을 무엇으로 만드나"는 검증됐지만, **"사용자 홈에 어떻게 보이나"**가 미해결로 남아 이 세션이 시작됐다. 설계하는 동안 Claude의 직관이 **다섯 번 무너졌고**, 그 과정이 본문이다.

1. **쇼핑 비교 데모(decision_compare)** = 트랙 C 킬러 → **overfit으로 폐기.** 같은 품목 N개 저장 ≠ 비교 의도.
2. **주제 묶음을 회수의 1급 파이프라인으로** → **폐기.** 입자(granularity)는 질의 맥락이 정하므로 미리 materialize 불가.
3. **홈 = 안심 창** → **리마인더로 교정.** "정서적 안심"이 아니라 "까먹은 것·다시 볼 것을 꺼내줌".
4. **주간 리포트 + 트랙 C 통합(A안)** → **철회.** 화면에서 "카테고라이징이 두 종류"로 드러나 어색.
5. **핵심 도달**: **회수는 분류가 아니다.** category 통계도, 주제 묶음 라벨도 노출하지 않는다. 회수 = "다시 볼 기억 떠올림".

**확정 UX**: 회수 3단 — **① 홈 "한 칸"(고정 틀 + 가장 가치 높은 1개 미리보기) → ② 자세히 보기(통일된 카드 목록) → ③ 기록 상세(종류별 디테일).**

## 1. 출발 — 어디서 이어받았나

선행 3 journal(`…-design`(3트랙 기획)·`…-tech-design`(트랙 C MVP 기술)·`…-bundling-validation`(묶음 메커니즘 실증)). 묶음을 *무엇으로* 만드는지는 실데이터로 검증됐으나, **사용자가 홈에서 회수를 어떻게 만나는지**는 비어 있었다. "문서를 신뢰하지 말고 네 생각을 말하고 codex와 3턴 이상 토론하라"는 지시로 출발.

---

## 2. codex 4턴 토론 — 묶음·비교·안심창이 무너지다 ★

Claude가 선행 합의를 의심해 3개 반론을 세우고 codex(GPT-5.5, read-only)와 토론. 송준서가 중간에 전제를 연쇄 교정하며 결론을 끌었다.

### 반론 → codex 판정
- **반론1(묶음 1급화 = 과설계)**: ACCEPT. 트랙 C 본질은 "새 이벤트 → 1:1 소환"이고 묶음은 사후 집계. 단 codex 보강 — connected component도 transitive magnet 위험, bounded ego-network로.
- **반론2(헨리넥 과분할 = 프롬프트 아닌 구조 문제)**: ACCEPT(더 강하게). **입자는 질의 맥락이 정한다** — "헨리넥 살까"면 품목군, "무신사 스탠다드 살까"면 특정 상품. 라벨을 batch로 미리 굳히면 절반의 질의에서 틀린다. "trigger-time retrieval"을 표방하며 실제론 "precomputed topic inventory"를 만든 모순.
- **반론3(쇼핑 비교 집중 + 실험C 과장)**: PARTIAL. 실험 C는 묶음 판단을 오라클로 고정해 ANN만 측정 → "강하게 지지"는 과장(정직한 한계).

### 송준서의 연쇄 교정 (결정을 끈 축)
- **교정①**: "적은 시스템은 트레이드오프 입력일 뿐 **완성도가 더 중요**" → "단순해서 자른다"는 1턴 논리 무효화.
- **교정②**: 홈은 "안심"이 아니라 **리마인더**(까먹은 것·다시 볼 것을 꺼내줌) → cold start 빈손이 결함에서 정상으로(리마인드할 게 없으면 안 보여주는 게 옳다).
- **교정③**: 사용자는 **키보드·앱 켜기를 싫어함** → 채팅을 메인 회수로 두면 안 되고, 앱 밖에서 부르는 **notification이 메인 능동 장치**. design의 "트랙 C 푸시 금지"는 능동성을 스스로 죽이는 모순 → 폐기. 단 "누르고 싶은" 품질 극대화("애매하면 안 보낸다"). 구조는 **hook produces(저장 시 후보 생산) / cron decides(주기 재평가 후 발송)**.
- **교정④**: "**D-day(시간 제약) 고려하지 마라** — 17일에 55k줄 만든 팀, 현실 점검은 무의미." → 우선순위는 시간이 아니라 의존·완성도로.

> notification 메인(교정③)은 **앱 밖 획득** 갈래로, 이 세션의 홈 UI 작업과는 별도 트랙으로 남겨졌다(§5).

## 3. 홈 UX — "분류"가 두 번 무너지다 ★

홈 preview(mock)를 그리며 사고가 더 깊어졌다.

### 3.1 비교 카드 overfit (송준서 제기)
- Claude는 decision_compare(헨리넥 3벌 비교표: 가격·소재·핏 우열)를 히어로로 그림.
- **송준서**: "같은 품목 둘 저장 = 비교 의도라고 퉁치나? 둘 다 사려는지·선물인지·월급날 하나만인지·가격 고민인지 다 다른데."
- **교정**: 비교표는 *한 가지 의도*에만 맞는 overfit. design의 **"단정 금지"**("샀나요❌ → 결정하셨어요⭕")보다 더 큰 단정(행위 자체를 가정). 비교는 회수가 아니라 **결정 대행**이라 트랙 C에 끼우면 회수 앱이 쇼핑 어시스턴트로 샌다. → 비교표 제거, **의도 단정 없는 "관련 기억 회수"**(각 기록의 *그때 저장 맥락*만)로.

### 3.2 주간 리포트 통합(A안) → 카테고라이징 두 종류 (송준서 제기)
- bundling-validation §1/§8의 A안대로 "모찌가 모아뒀어요 = 시간축(weekly coarse) + 맥락축(트랙 C fine)"을 한 화면에 통합.
- **송준서**: "카테고라이징이 두 번 되는 게 어색하다. **왜 모찌에 분류가 두 종류지?** 카테고리 안의 카테고리처럼 느껴진다."
- Claude 1차 답("모찌는 분류를 안 보여주는 앱이다 — 4-Intent 비노출 철학") → **송준서 정정**: "4-Intent를 *분리* 안 한다고 했지, 분류 자체를 안 보여준다고 적혀 있나?" Claude의 **과잉 일반화 오류 인정** — 실제로 `category`(일상/쇼핑)는 `weeklyReplayCard`에서 이미 노출 중.

### 3.3 핵심 도달 — 회수는 분류가 아니다
- 진단: weekly의 `쇼핑21`(coarse)도, 트랙 C의 `유니클로5`(fine)도 **둘 다 주제 분류**다. "시간축 vs 맥락축"은 틀린 프레이밍 — 같은 주제축의 다른 해상도라 "카테고리 안의 카테고리"로 보인 것.
- 더 근본: **분류는 리마인더의 본질이 아니다.** "이번주 쇼핑 21개"는 회고·통계지 "다시 볼 가치 있는 걸 떠올려주기"가 아니다.
- **결론**: 회수 화면에서 분류(coarse 통계 칩·주제축 라벨)를 **전부 제거**. category는 탐색·통계(weeklyReplayCard)의 역할로 분리. 회수는 분류 0개 노출 → "왜 두 종류?" 의문이 생길 자리가 사라진다.

### 3.4 정보 과부화·비일관·들쭉날쭉 (송준서 제기)
- **송준서**: "회수 카드를 홈에 여러 개 깔면 과부화. 카드별 일관성 없고, 언제는 뜨고 언제는 안 뜨고."
- 진단: 회수는 본질상 **가변**(조건부·다양)인데 홈은 **안정**을 요구. 가변적인 걸 안정 표면 위에 날것으로 깐 게 문제.
- **해법(3단)**: 가변성을 고정 틀 뒤로 숨긴다. **홈엔 회수 "한 칸"**(자리·틀 고정, 가장 가치 높은 1개만 미리보기, 비면 "지금은 없어요"로 채워 레이아웃 안 출렁) → **자세히 보기**에서 **통일된 카드 목록**(전부 같은 틀, 종류 차이는 안 보임) → **기록 상세**에서 종류별 디테일.

## 4. 확정된 회수 UX

- **정의**: 회수 = 분류가 아니라 **"다시 볼 기억 떠올림"**(리마인더). category·주제 묶음 라벨을 사용자에게 노출하지 않는다.
- **3단 구조**:
  - **① 홈 "한 칸"** — 고정 자리·고정 틀. "다시 보면 좋을 기억 N개" + **가장 가치 높은 1개 미리보기 한 줄**(안 눌러도 떠오르게). 미션("앱 켜면 바로") 충족.
  - **② 자세히 보기** — **통일 카드**(썸네일 + 이유 칩 + 제목 + 한 줄 + 시점). 지식/관련/맥락이 모두 같은 틀. 묶음은 "관련 기억 N개"만 덧붙이고 **카테고리로 승격하지 않음**.
  - **③ 기록 상세** — 종류별 디테일: 지식=모찌가 정리한 핵심 / 관련=관련 기억 목록(그때 맥락) / 맥락=왜 지금 이어지는지 연결 설명.
- **"왜 지금 떠올렸나"**(이유 칩)는 회수 신호의 표현이지 분류가 아니다: 잊기 전에 / 관련해서 여러 번 / 요즘 자주 / 지금 맥락과 이어져요.
- **썸네일은 실제 캡처 이미지**(mock은 SF Symbol placeholder).

## 5. 미해결 / 후속

1. **notification 메인 표면(앱 밖 획득)** — 교정③의 별도 갈래. **설계·근거는 자매 journal `2026-06-15-proactive-recall-notification-decision.md`** (push 금지 폐기 / "누르고 싶은" 발송·보류 판정 기준 / hook produces·cron decides / 위험 통제). 구현은 미완. landing은 이 세션의 회수 목록·상세로 착지한다.
2. **홈 "한 칸" 빈 상태** — 회수 없을 때 카피·톤.
3. **다시 볼 가치 랭킹 공식** — `재방문가치 × (0.7 + 0.6 × 현재관련성)`(곱셈 함정 회피: context는 0~1 곱이 아니라 바닥 있는 증폭). 실측 미정.
4. **통일 카드/상세 디테일** — 묶음 카드가 여전히 "분류"로 읽히지 않는지 실기기 확인.
