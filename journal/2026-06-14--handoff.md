## 4. 결정 / trade-off (왜 이렇게 했는가)

- **키워드 추출 = 메인(이미지) > tool 내부** — exp6~7 generic 실패의 근본원인이 미니가 빈약 summary 로 키워드 생성. 이미지를 보는 메인이 queries+category 를 주면 제거(가설1, baseline 으로 검증됨).
- **critique loop 제거** — exp 에서 refine 기여 낮음 + codex 가 잡은 덮어쓰기 버그. search 1회+judge 게이트로 충분.
- **platformContext URL 게이트(A2, 제거 아님)** — url-bearing 캡처(공유시트 youtube/insta)엔 platformContext 가 정본. 완전 제거(A1)는 회귀. 스크린샷(url 없음)에만 recover/finder 로 프롬프트 게이트.
- **recover 3단계** — 무키 검색은 막 올라온 영상 인덱스 지연·봇차단에 약함. confidence 낮으면 YouTube Data API(uploads 직접조회=인덱스 우회, 1 unit). 그래도 못 찾으면(멤버십·모호) 채널 주소라도(미션 "회수의 능동 주체는 모찌").
- **recovered=false 가 옳다** — 못 찾는 영상은 누구도(Claude 포함) 텍스트로 못 찾음. 무리해서 엉뚱한 영상 반환 안 함(judge 게이트 철학과 동일).
