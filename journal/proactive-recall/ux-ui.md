# 능동 회수 UX/UI — 화면 설계 (2026-06-16)

> 정본 `2026-06-15-…-ux-decision`(회수 3단) 정제 + landing 매핑(#8)·홈 IA(#5) 결정. **발송은 `notification-agent.md`, 데이터 모델은 `schema.md`.** 미구현(mock만: `RecallHomeFeedMock.swift`).

---

## 0. 한눈에

- **회수 = 분류가 아니다.** category·주제 묶음 라벨을 사용자에게 노출하지 않는다. 회수 = "다시 볼 기억 떠올림"(리마인더).
- **3단 구조**: ① 홈 "한 칸" → ② 자세히(통일 카드 목록) → ③ 기록 상세(종류별 디테일).
- **알림 landing**: 단건은 ③ 상세 직행, `kind`는 상세 섹션 형태를 정함.

---

## 1. 회수란 — 분류가 아니다 (정본 ux §3–4)

- 정의: 회수 = **"다시 볼 가치 있는 기억을 떠올려주기"**(리마인더). 통계·회고(주제 분류)가 아니다.
- category 통계 칩, 주제축 라벨을 회수 화면에 **0개 노출**. (category는 탐색·통계 역할로 분리 — weekly 등.)
- cold start 빈손은 결함이 아니라 정상(리마인드할 게 없으면 안 보여주는 게 옳다).

## 2. 3단 구조 (정본 ux §4)

- **① 홈 "한 칸"** — 고정 자리·고정 틀. "다시 보면 좋을 기억 N개" + **가장 가치 높은 1개 미리보기 한 줄**(안 눌러도 떠오르게). 비면 "지금은 없어요"로 채워 레이아웃 안 출렁. 미션("앱 켜면 바로") 충족.
- **② 자세히 보기** — **통일 카드**(썸네일 + 이유 칩 + 제목 + 한 줄 + 시점). 지식/관련/맥락이 모두 같은 틀. 묶음은 "관련 기억 N개"만 덧붙이고 **카테고리로 승격하지 않음**.
- **③ 기록 상세** — 종류별 디테일(§5).
- **썸네일 = 실제 캡처 이미지**(mock은 SF Symbol placeholder).

## 3. 이유 칩 — "왜 지금 떠올렸나" (정본 ux §4)

회수 신호의 표현이지 분류가 아니다: **잊기 전에 / 관련해서 여러 번 / 요즘 자주 / 지금 맥락과 이어져요.**

## 4. 알림 → landing 매핑 (결정 #8)

**핵심: landing은 `kind`가 아니라 카디널리티가 정한다.** `kind`는 상세 화면 안의 섹션 형태를 정한다. 단 **"다건"은 두 종류이고 서로 다르게 착지한다 (doc-guardian M-1):**
- **recall 다건**(한 맥락의 관련 기억 N개) → ③ 상세가 "관련 N개"를 **품음**.
- **bundle**(서로 다른 알림을 같은 날 합침) → ② 자세히(목록). 단 묶기는 콜드스타트 후속 → **나중**.

| kind | 성격 | landing | 상세(③) 섹션 | primary 액션 | 보조(피드백) |
|---|---|---|---|---|---|
| `deadline` | 리마인드 | ③ 직행 | 일정/할일 정보·날짜 | **완료** · 스누즈 | — |
| `nudge` | 리마인드 | ③ 직행 | 할일 정보 | **했어요** · 나중에 | — |
| `spaced` | 회수 | ③ 직행 | 정리된 핵심(A-3) + 원본 | **열기 / 원본 보기** | (도움됐어요·관심없음은 dismiss 사유로 강등) |
| `recall` | 회수 | ③ 직행(관련 N개 품음) | 관련 기억 + 이유 칩 | **열기** | (관련없어요는 dismiss 사유) |

**미션 정합 (codex-8) ★**: 상세의 **primary 액션은 "사용자 목적 수행"**(열기/원본/완료)이지 "모찌 품질 평가"가 아니다. "도움됐어요/관심없음" 같은 피드백을 primary로 두면 미션("필요한 기억은 *떠오른다*")이 "사용자가 모찌를 평가한다"로 변질된다. **학습은 open/`item_access_log`(행동 신호)를 우선**으로 삼고, 명시 피드백은 secondary/dismiss 사유로 낮춘다.

**"그만" scope 1:1 매핑 (codex-7)**: 액션 문구 ↔ 서버 상태전이를 고정 — "이 기억 그만"=`plan.cancelled` / "이 주제 줄이기"=theme cooldown / "회수 알림 끄기"=설정. "그만" 눌렀는데 비슷한 게 또 오면 신뢰가 깨진다.

**라우팅 규칙:**
- **단건 알림(기본) → ③ 기록 상세 직행.** 기존 `mochiItemID`/`sourceIntentID` deep-link(iOS `openDetailFromNotification`, PK→Local 역매핑) 재사용. **로컬 역매핑 실패 시 `recallEventID`로 서버 fetch fallback**(codex-2 — 빈 상세 금지).
- **① 홈 한 칸** = 알림 아닌 **in-app 진입**(앱 직접 켤 때). ②③ 화면을 공유.

## 5. 상세 화면(③) = 단일 화면 + 섹션 분기

`MemoryDetail` **한 화면**이 `intent_type`/`kind`를 보고 섹션을 다르게 렌더(일정이면 일정+액션, 지식이면 정리, 회수면 관련기억+이유칩). **kind마다 별도 화면을 만들지 않는다.**

- 지식(spaced) = 모찌가 정리한 핵심 + 원본 링크(원본 대체 금지) / 관련(recall) = 관련 기억 목록(그때 맥락) / 맥락 = 왜 지금 이어지는지 연결 설명.
- **응답 액션 = proposal 카드 패턴 재사용**(`ProposalCardView` confirm/cancel — "회수 = 모찌가 먼저 띄우는 proposal"). 단 §4대로 **primary는 목적 수행, 피드백은 보조**. 결과가 lifecycle 닫기(완료/그만→archived/cancelled) + 학습 신호(`outbox.opened_at`/`dismissed_at`) + 다음 간격(spaced 전진).
- **단정 금지**: 항상 확인 질문 톤("샀나요"❌ → "결정하셨어요?"⭕).

## 5a. 접근성 (codex-9)

- **이유 칩**: VoiceOver에서 "회수 이유: 잊기 전에"처럼 의미가 읽히게 라벨링(칩 색·아이콘만으론 안 됨).
- **홈 한 칸 preview**: Dynamic Type 확대 시 **2줄까지 확장**(한 줄 고정으로 잘리지 않게). 레이아웃 안정은 유지하되 텍스트는 안 자름.
- **상세 액션**: Dynamic Type 큰 글자에서 가로 버튼이 잘리면 **세로 스택 전환**. destructive한 "그만"은 primary confirm과 **시각적으로 분리**(오탭 방지).

## 6. 홈 정보구조(IA) (결정 #5)

현 홈(`HomeFeature`)은 3섹션(needsReview / analyzing / recent, 셋 다 비면 사라지는 일시 섹션). 여기에 회수 "한 칸"을 더한다.

**권장 배치(위→아래):**
1. **needsReview** — "지금 확인해 주세요"(긴급 예외, 비면 사라짐)
2. **회수 한 칸** — "다시 보면 좋을 기억"(고정 틀, 비면 "지금은 없어요") ← needsReview 다음 상단에 둬 "앱 켜면 바로 떠오름" 충족
3. **analyzing** — "정리하고 있어요"(접힘)
4. **recent** — "최근에 보낸 것들"

- 회수 한 칸만 고정 틀(나머지는 일시). 회수의 가변성을 고정 틀 뒤로 숨겨 레이아웃 안정.
- `HomeFeature`에 회수 한 칸 state·action 추가(새 섹션).

> **06-08 "모찌가 정리했어요" 처리결과 보드**: 정본 밖(ux-decision이 "안심창→리마인더"로 일부 정정). 회수 한 칸(가변 리마인더)과 역할이 달라(보드=항상참 안심) 지금 스코프에 안 넣음. recent 대체 여부는 **열린 향후**.

## 7. 미결 / 후속

- **다시 볼 가치 랭킹 공식** — "가장 가치 높은 1개"를 고르는 식: `재방문가치 × (0.7 + 0.6 × 현재관련성)`(곱셈 함정 회피). 실측 미정.
- **홈 한 칸 빈 상태** 카피·톤.
- **통일 카드/상세 디테일** — 묶음 카드가 "분류"로 안 읽히는지 실기기 확인.
- **트랙 C 회수 본체**(관련 기억 소환 메커니즘) — A/B 다음 단계(범위 내), `tech-plan.md` §8 P7–P9.
