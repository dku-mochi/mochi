# 실기기 E2E 체크리스트 (2026-07-14)

사용자가 실기기에서 직접 돌리는 검증 목록. AI 는 시뮬레이터·실기기 실행이 금지라(빌드 분담, CLAUDE.md §4)
여기 항목들은 **사람 검증이 최종 게이트**다. 각 항목은 통과 시 `[x]`, 실패 시 아래 "발견" 절에 증상을 남긴다.

전제: develop 작업트리 빌드(미커밋 변경 포함 — backend `/search` answer 제거·알림 선호·시스템 캘린더
자동 관리), 백엔드는 배포본(mochi-svc) 또는 로컬 LAN. 캘린더·미리알림·알림 권한은 시나리오별 명시.

## (a) 채팅 알림 CRUD

- [ ] "내 알림 뭐 있어?" → 예정 알림 목록 카드가 실제 `/recall/upcoming` 과 일치
- [ ] "내일 오는 알림 있어?" → 날짜 필터가 맞게 걸린 목록 (KST 경계 — 자정 직전/직후 항목 포함 여부 확인)
- [ ] 카드에서 시각 이동 확정 → 알림 페이지(§3.4c)·`/recall/upcoming` 재조회에 새 시각 반영
- [ ] 카드에서 취소 확정 → 목록에서 사라지고 재fetch 에도 부활 없음
- [ ] 만료 카드(이미 발송·취소된 대상) 확정 → "기록이 이미 없어요" 만료 처리(에러 아님)

## (b) 회수 피드 reaction

- [ ] 홈 회수 히어로 카드 열기(`opened`) → 상세 닫고 복귀 시 카드가 착지 후 사라짐
- [ ] "그만 보기"(`stop`) → 토스트 + 히어로에서 제거, **앱 재시작 후 재fetch 에도 부활 없음** (stop 신호 유실 fix 검증)
- [ ] 회수 목록(모두 보기)에서도 같은 반응이 홈 히어로와 정합

## (c) 알림 전역 선호 토글 (오늘 신설)

- [ ] 설정 → "먼저 떠올려주는 알림" off → 예정 회수 알림 시각에 발송 스킵, 서버 로그 `skip_reason=preference_off`
- [ ] off 동안에도 인앱 표면(홈 히어로·알림 페이지) 불변
- [ ] on 복귀 → 다음 예정부터 발송 재개 (이미 스킵된 회차는 소급 발송 없음)
- [ ] "헷갈릴 때 물어보는 알림" off → needs_review 분석완료 alert 미수신, on 복귀 시 재개

## (d) 시스템 캘린더·미리알림 자동 관리 (유닛 2 — 자동 관리 전환)

> 원래 "동의 탭 등록" 시나리오였으나 2026-07-14 사용자 결정으로 **완전 자동 관리**로 전환됨(UX_SPEC §1.5).

- [ ] 채팅 일정 확정 → (권한 프롬프트 최초 1회) 아이폰 **캘린더 앱**에 이벤트 자동 등록 (시간 없으면 종일, end_date 면 기간)
- [ ] 채팅 할 일 확정 → **미리알림 앱**에 자동 등록 (deadline 시각 포함)
- [ ] 채팅으로 날짜 수정 확정 → 캘린더 이벤트가 새 날짜로 **따라 이동** (중복 이벤트 0)
- [ ] 상세·캘린더 탭에서 todo 완료 체크 → 미리알림 항목이 **완료 처리**, 해제하면 미완료 복귀
- [ ] 기록 삭제 → 연결된 캘린더/미리알림 항목 **자동 제거**
- [ ] 캡처(스크린샷/ShareExt) 분석이 확정 schedule 로 나온 경우 → 확정 탭 없이도 캘린더 자동 등록 (앱 실행 중)
- [ ] 캘린더 앱에서 이벤트를 **직접 삭제** → 모찌가 다시 만들지 않음(tombstone — 사용자 삭제 존중)
- [ ] 같은 기록이 어떤 경로(재실행·재분석·pull)로도 **두 번 등록되지 않음**
- [ ] 설정 → 연동 → "캘린더·미리알림 자동 등록" off → 신규 등록·갱신 중단(기존 항목 불변), on → 밀린 확정분 즉시 따라잡기
- [ ] 권한 거부 케이스: 채팅 확정 시 failed 카드 + "설정에서 권한 켜기" → 설정에서 허용 후 앱 복귀 → 밀린 등록 자동 따라잡기

## (e) 앱 미실행 자동화 — silent push + 백스톱

- [ ] **앱을 백그라운드로 보낸 상태**에서 ShareExt 로 과제 공지 캡처 → 앱을 다시 열지 않고 몇 분 내 아이폰 캘린더에 마감이 선다 (silent push → background reconcile → EK 등록)
- [ ] **앱 강제종료(스와이프 킬) 상태**에서 캡처 → silent push 는 OS 가 앱을 깨우지 않을 수 있음(미보장 규격) → **다음 앱 실행 시** 캘린더가 전부 맞춰져 있는지 확인 (reconcile 백스톱이 최종 보증)
- [ ] silent push 가 사용자 노출 알림(배너·소리·배지)을 만들지 않는지 확인
- [ ] 알림 전역 선호 off 상태에서도 silent 동기화 push 는 동작 (데이터 신호 — 선호 게이트 무관, 회귀 금지)

## (f) 관찰 후 결정 항목

- [ ] **채팅 프롬프트 가이드 ③** — "알림 확인" 계열 질문에서 `list_notifications` 대신 `propose_reminder` 를 오선택하는 사례가 실재하는지 실사용 중 관찰. **관찰 결과가 쌓이기 전에는 프롬프트를 손대지 않는다** — 오선택이 실재하면 케이스 하드코딩이 아니라 research-first(기준+why, Gemini/skill-creator 가이드 조사)로 결정한다는 기존 방침 유지.
